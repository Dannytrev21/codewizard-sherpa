## Conflict-resolution priority (Consistency > Coverage > Test-Quality > Design-Patterns)

Three near-conflicts surfaced; all resolved Consistency-first:

SUT-digest and cassette-corpus-digest invalidation are unit-tested in S2-03 via `compose_cache_key`'s per-field uniqueness + positional-swap-resistance ACs. Consistency wins → keep this story scoped to the §Step 5 cases. SUT-digest / cassette-corpus-digest invalidation deferred to Notes as a future integration story candidate (Phase 7+ when the real SUT lands and `sut_digest` changes meaningfully).

2. **Coverage** wanted a single-case test that exercises the **(2) re-sign-then-rerun** semantic (edit `digests.yaml` after the case edit, expect 9 hits + 1 miss); **Consistency** finds High-level-impl.md §Step 5 says "whitespace edit to one `case.toml` invalidates exactly that case" — ambiguous between (1) structural digest defense and (2) re-signed propagation. The story's primary assertion is (1) because that's the load-bearing structural defense per S2-02. (2) is the *semantic* invalidation but it requires re-signing — a second-order operation. Coverage adds (2) as an optional secondary AC (AC-SINGLE-RESIGN) with a clear "the structural defense (1) is the load-bearing test; (2) is a behavioral sanity check on the cache-key composition". Both surfaced. Test-Quality endorsed.

3. **Design-Patterns** proposed extracting the cache-state assertion helper (`_assert_all_cache_hits`, `_assert_zero_cache_hits`) into a shared `tests/integration/_cache_helpers.py` module; **Rule 2** says three similar lines is better than premature abstraction. With only two integration tests in this story, the helpers stay inline. Surfaced in Notes as a rule-of-three trigger candidate when S6-03 (distroless E2E) ships its own cache-hit assertion.

## Findings

### Consistency critic (6)

- **F-CON-1 (BLOCK) — env-var fixture (`CODEGENIE_EVAL_CACHE_DIR/RUNS_DIR/SUT`) is not an S4-02 contract.** Identical to S5-05 F-CON-1. The `fresh_eval_env` fixture monkeypatches three environment variables, none of which the CLI reads. S4-02 HARDENED takes `--out` (chain-write dir), `--bench-root` (case-walk root), and `--cache-dir` (added by S5-05 as a one-flag extension); SUT resolution goes through `codegenie.eval.sut_registry.resolve_sut(name)` against `default_sut_registry` populated at module-import time. **Resolution:** delete the env-var fixture; use `tmp_path`-derived flag overrides passed to `CliRunner.invoke(eval_group, ["run", "--task-class=vuln-remediation", "--out", str(tmp_runs), "--bench-root", str(tmp_bench), "--cache-dir", str(tmp_cache)])`. SUT registration is the autouse conftest at `tests/fixtures/sut/conftest.py` (already shipped by S5-05).

- **F-CON-2 (BLOCK) — subprocess-spawn cannot reach a test-only SUT.** Identical to S5-05 F-TQ-2. `subprocess.run([sys.executable, "-m", "codegenie", "eval", "run", ...])` spawns a fresh Python process whose `default_sut_registry` is empty (the autouse conftest does not propagate across process boundaries); `resolve_sut("vuln-remediation")` raises and the run exits 3. **Resolution:** replace `subprocess.run` with `from click.testing import CliRunner; result = CliRunner().invoke(eval_group, [...])`. In-process. Subprocess-shape coverage stays the nightly canary's job (real SUT) per S5-05 F-CON-1's deferral.

- **F-CON-3 (BLOCK) — JSONL shape contradiction.** Tests parse `c["score"]["cost_usd"]` (nested under "score") and `c["score"].get("cache_hit")` (nested). S4-02 HARDENED AC-10 pins the per-case line as **flat**: `{"kind":"case","case_id":str,"score":float∈[0,1],"passed":bool,"breakdown":{...},"failure_modes":[...],"cost_usd":float,"wall_clock_s":float}` — `BenchScore` is dumped at the top level (since `BenchScore.score` is the scalar; nesting it under another `"score"` key would shadow). The cache_hit field, when added (see F-CON-4), surfaces at the same flat level. **Resolution:** rewrite every JSONL access to `c["cost_usd"]`, `c["cache_hit"]`, `c["wall_clock_s"]` (note: also `wall_clock_s` not `wall_clock_ms`). The `case_id` lives at top-level on the same line.

- **F-CON-4 (BLOCK) — `BenchScore.cache_hit` field addition silently extends a HARDENED contract.** S1-02 HARDENED AC-2 pins `BenchScore`'s field shape via a structural walk that asserts the cardinality of wire types is exactly 5 and that every model is `frozen=True, extra="forbid"`. Adding a new optional field with default `False` is an extension-by-addition (no edit to existing fields), but the change must be loud: a one-line addition to `BenchScore` that any reader notices. Two ACs cover this: (a) explicit pre-condition that `cache_hit: bool = False` is added under `BenchScore` (with `Field(default=False)` and a docstring), (b) the runner (S3-02) stamps `cache_hit=True` when serving from cache. **Resolution:** added AC-CACHE-HIT-FIELD (pinned to `BenchScore.cache_hit: bool = False`, `extra="forbid"` preserved) and AC-RUNNER-STAMP (the runner sets `True` on serve-from-cache). The S1-02 snapshot regeneration (S7-02) is folded into AC-SNAPSHOT-REGEN.

- **F-CON-5 (BLOCK) — `Depends on:` line incomplete.** Original named only S5-05. The story exercises six other HARDENED stories' contracts at runtime: S4-02 HARDENED (CLI flags `--out`/`--bench-root`/`--cache-dir`, `default_sut_registry` resolution, flat JSONL shape), S4-01 HARDENED (exit code 0 for the happy path, `_EXIT_CODE_TABLE` mapping), S2-03 HARDENED (`compose_cache_key`, `get`/`put`, content-addressed file layout), S2-02 HARDENED (loader + canonical case-dir digest, `BenchCaseDigestMismatch` on stale digest), S1-02 HARDENED (`BenchScore` field shape — the AC that this story extends by one field), S3-02 HARDENED (runner fan-out + cache probe + cache-write — the only seam that can stamp `cache_hit=True`). Mirror S5-05 F-CON-4's quality bar. **Resolution:** rewrote `Depends on:` to enumerate all seven predecessors with HARDENED contract markers and per-citation rationales.

- **F-CON-6 (HARDEN) — `ADRs honored` incomplete.** Original named ADR-0001 and ADR-0002. Missing: Phase 0 ADR-0001 (BLAKE3 chokepoint — the cache key flows through `codegenie.hashing.content_hash_bytes` per S2-03), production ADR-0009 (humans always merge — the test's cache-correctness gate produces evidence the curator commits to git but does not auto-merge), production ADR-0015 (calibration-deferred — the lower_bound_95 stability test is a precondition for Phase 13 calibration). **Resolution:** expanded with per-ADR rationale.

### Coverage critic (5)

- **F-COV-1 (HARDEN) — `cache_hit=True ⇒ cost_usd == 0.0` property test mentioned in Refactor but not in ACs.** Original §Refactor "the `cache_hit` field is part of the wire contract; document on `BenchScore` and add a property test". A note in the §Refactor section is not a CI gate; the executor's validator pass would not catch its absence. **Resolution:** promoted to AC-PROPERTY-HIT-IMPLIES-ZERO-COST — a Hypothesis property test under `tests/unit/eval/test_cache_hit_property.py` (or appended to S2-03's `test_cache.py`) asserts `BenchScore(cache_hit=True, ...).cost_usd == 0.0` is the **only** valid combination by validator (a `model_validator(mode="after")` raises on `cache_hit=True and cost_usd > 0`). The model-level invariant is enforced by Pydantic; the property test pins the invariant against arbitrary `BenchScore` shapes drawn by Hypothesis. **Note:** ADR amendment surfaced — the model-validator addition is structural; the executor's `phase-architect` pass logs it. If the model-validator approach is rejected by phase-architect (e.g., for ergonomic reasons in the cost-cap path where partial reports might surface `cache_hit=False, cost_usd > 0`), fallback to a property-test-only enforcement and document the gap.

- **F-COV-2 (HARDEN) — README "Cache behavior" section mentioned in Refactor but no AC anchors the assertion.** Same shape as F-COV-1: an English-only commitment in §Refactor is not a CI gate. **Resolution:** promoted to AC-README-CACHE-BEHAVIOR — `bench/vuln-remediation/README.md` contains a "Cache behavior" section that (a) names the two integration tests by file path, (b) lists the six cache-key inputs verbatim (`case_digest`, `sut_digest`, `rubric_digest`, `cassette_corpus_digest`, `harness_version`, `cassette_canary_pin`), (c) documents the signed-content-addressed semantics ("you cannot edit one case and let the cache invalidate; you must re-sign in digests.yaml"). The integration test asserts the section's existence and the verbatim presence of the six input names by string match. Mutation-resistant: any drift in the cache-key inputs documentation surfaces.

- **F-COV-3 (HARDEN) — `complete is True` invariant missing on warm rerun.** S4-02 AC-10 pins `agg["complete"] is True` on the happy path. The story's AC-1 (warm rerun) does not assert `complete`. A regression in the cost-cap accounting could produce a warm-rerun report with `complete=False` and the story's tests would still pass on `cost_usd` and `cache_hit`. **Resolution:** AC-1 now asserts `agg["complete"] is True`, `agg["isolation_class"] == "subprocess"`, and `agg["chain_head"]` is truthy + equals the on-disk record's `chain_head` (mirrors S5-05 AC-CHAIN-EXTEND).

- **F-COV-4 (HARDEN) — single-case re-sign-then-rerun semantic untested.** §Notes §1 documents the two interpretations; the original ACs only cover (1) (structural digest mismatch raise). (2) — re-signing `digests.yaml` after the case edit so `case_digest` matches and the cache miss serves only that one case — is the **actual** "single-case invalidation" semantic. (1) tests the loader; (2) tests the cache key composition. **Resolution:** AC-SINGLE-RESIGN added as a secondary test. Invokes the operator-side `scripts/sign_bench_digests.py` (S5-05 F-DP-2 — parameterized over `--task-class` and `--bench-root`) against the copied `tmp_bench`, edits one case's `input/<file>`, re-runs `sign_bench_digests.py` to update `digests.yaml`, then re-invokes `eval run`. Asserts: 9 cases `cache_hit=True`, exactly 1 case `cache_hit=False`. This is the cache-key composition gate; (1) is the loader gate.

- **F-COV-5 (HARDEN) — wall-clock budget needs jitter resistance.** AC-1's `elapsed <= 8.0` is a hard fail. CI runner contention can spike this. S5-05 AC-3a uses the same shape (`elapsed < 90.0` with stub SUT) and stays green because 90 s has generous headroom over the ~3 s actual runtime. Here, the 8 s budget is the High-level-impl.md §Step 5 floor; if CI runners flake at 7.5 s, the test will flake. **Resolution:** AC-1 splits the budget into two assertions: (a) hard fail `elapsed <= 12.0` (50% headroom — flake-safe), (b) regression diagnostic `elapsed <= 8.0` (the §Step 5 target; if exceeded, structlog-warn but do not fail). The diagnostic-only assertion surfaces drift without flaking CI. Mirrors S2-03 HARDENED's pattern of separating the contract from the regression alarm.

### Test Quality critic (4)

- **F-TQ-1 (BLOCK) — env-var fixture would never green.** See F-CON-1; resolution shared.

- **F-TQ-2 (BLOCK) — subprocess-spawn would never reach the test SUT.** See F-CON-2; resolution shared.

- **F-TQ-3 (HARDEN) — `BENCH = REPO_ROOT / "bench" / "vuln-remediation"` mutates the real working tree.** Identical to S5-05 F-TQ-3. The cache_invalidation tests append `b"\n"` to `bench/vuln-remediation/rubric.py` and to a real case input file. Under pytest-xdist, parallel test workers race on the same file; a crash mid-test leaves the working tree dirty; CI bisection over a dirty tree is undefined. **Resolution:** both tests use `shutil.copytree(REPO_ROOT / "bench" / "vuln-remediation", tmp_bench / "vuln-remediation")` at fixture setup; all mutations target `tmp_bench`; `--bench-root` points the CLI at `tmp_bench`. The real tree is untouched; the test is parallel-safe.

- **F-TQ-4 (HARDEN) — cache-hit detection's "OR equivalent" weakens the gate.** Original AC: "asserts the per-case `cost_usd` signal *and* an explicit `cache_hit: bool` (or equivalent) field". The "or equivalent" escape hatch lets an executor implement a `wall_clock_ms < threshold` proxy instead of the explicit field; the proxy is fragile (depends on stub SUT speed) and incidental coupling. **Resolution:** AC removed the OR clause; mandates the explicit `cache_hit: bool` field on `BenchScore` (per AC-CACHE-HIT-FIELD). The fallback proxy is documented in Notes as the "if S1-02 cannot be extended for some reason" escape hatch only.

### Design Patterns critic (3 promoted to AC + 1 surfaced)

- **F-DP-1 (PROMOTED to AC-CACHE-HIT-FIELD) — `BenchScore.cache_hit: bool` extension is the right open/closed extension point.** The arch's §Process view line 856 names `cache_hit: bool` as a span attribute; promoting it to a wire-type field gives every consumer (snapshot tests, audit chain, the per-case JSONL) a typed surface to depend on. Newtype discipline does NOT apply (it's a literal boolean, not a domain identifier). The Pydantic model-validator (`cache_hit=True ⇒ cost_usd == 0.0`) makes illegal states unrepresentable. Resolution: pin via AC. The S1-02-cardinality assertion still passes (5 wire types, no new model); the BenchScore field count grows by 1 (which is what we want — the structural walk does not assert field-count cardinality, only model-count cardinality).

- **F-DP-2 (PROMOTED to AC-CONFTEST-REUSE) — autouse conftest from S5-05 is the SUT-registration seam.** The conftest at `tests/fixtures/sut/conftest.py` already monkeypatches `default_sut_registry` and imports `tests.fixtures.sut.deterministic_vuln_sut`. S5-06's tests live under `tests/integration/eval/` (the same parent the S5-05 conftest covers). Resolution: the story's TDD plan asserts the conftest covers `tests/integration/` (or moves the autouse coverage broader if needed); the tests do NOT redefine the SUT registration. Test under `tests/integration/eval/` will inherit the autouse fixture automatically.

- **F-DP-3 (PROMOTED to AC-RUNNER-STAMP-EXTENSION-POINT) — runner cache-hit stamping is a single seam.** S3-02 HARDENED is the runner fan-out; the cache-hit stamp happens at exactly one point: when `cache.get(cache_key, cache_dir)` returns non-`None`, the runner constructs the `BenchScore` with `cache_hit=True` (or `model_copy(update={"cache_hit": True})` if returning the cached score directly). Resolution: AC pins the seam location (`src/codegenie/eval/runner.py` — the cache-probe branch). A regression where the stamp is forgotten surfaces as the warm-rerun test failing with `cache_hit=False` and a diagnostic naming the seam.

- **F-DP-4 (surfaced) — `_assert_all_cache_hits` / `_assert_zero_cache_hits` helpers.** Two tests in this story; would be the second consumer if S6-03 adds a distroless cache-hit test. Rule 2 (three similar lines is better than premature abstraction) defers the extraction; surfaced in Notes as the rule-of-three trigger.

### Surfaced — endorsements (no edit)

- **Two scenarios in one test file is the right boundary.** `test_cache_invalidation.py` has two scenarios (rubric-edit-all + case-edit-one). Splitting into two files would be premature granularity; keeping them together as separate test functions in one file is right.
- **`try`/`finally` restore is correct for the in-tmp case.** Even though the mutation happens in `tmp_bench` (after F-TQ-3), keeping the `try`/`finally` is defense-in-depth — a crash between mutation and pytest tmpdir teardown still cleans up. Endorsed.
- **`# cache-bust\n` byte-content edit (not `touch`) is correct.** The cache is content-addressed (BLAKE3 over inputs); `touch` would not change the bytes. The story's Notes for the implementer explicitly documents this. Endorsed.
- **`isolation_class="subprocess"` assertion on the warm rerun.** Phase 6.5 emits one valid value today; asserting it is structural foresight at near-zero cost. Endorsed.
