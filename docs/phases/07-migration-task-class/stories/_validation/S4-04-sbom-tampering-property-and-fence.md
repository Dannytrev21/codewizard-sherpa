# Validation report — S4-04 Hypothesis SBOM-tampering property test + AST fence

**Validated:** 2026-08-14 (pre-executor pass)
**Validator:** phase-story-validator
**Verdict:** **HARDENED**
**Story file:** `docs/phases/07-migration-task-class/stories/S4-04-sbom-tampering-property-and-fence.md`

## Context

Pre-executor validation on a `Ready` (never-shipped) story. The story's core intent — two structural defenses (Hypothesis property test + AST-walk fence) that make Gap 3 a mechanically-enforced invariant — is architecturally sound and traces cleanly to `phase-arch-design.md §Gap 3` and §Testing strategy §Property tests. But **eight** structural issues need resolution before the executor picks it up: three block-severity (single-source-of-truth violation on the SBOM known-field catalog; factual mismatch between AC-2 Shape F and the shipped `SyftSbom`; missing execution precondition on S4-01/S4-02/S4-03 shipping the referenced adapter files); five harden-severity (marker choice ambiguity; meta-self-test pattern chosen over a cleaner walker-library shape used by every other Phase-7 fence; underspecified `Unknown.reason` allow-set in AC-3; `assume(...)`-based Shape D collision guard is rejection-sampling-shaped; Shape enum for Hypothesis-event completeness not surfaced); plus a nit around the exception-loud-fail discipline in AC-4.

## Context Brief

**Goal (verbatim from story):** Ship two structural defenses that make Gap 3 a mechanically-enforced invariant — (1) a Hypothesis property test drawing ≥ 100 adversarial `SyftSbom` instances and asserting every adapter run lands in a typed-safe state; (2) an AST-walk fence catching future drift into untyped SBOM content.

**Phase-arch constraints:**
- §Gap 3 (lines 1550–1554) — "Phase 7 adds a defensive guard inside the adapter: the adapter reads ONLY the fields it consumes (`locations[].layerID`, `name`, `version`) and never recurses into `extra` content. A fence test AST-walks the adapter."
- §Testing strategy §Property tests (line 1406) — verbatim AC: "100+ generated SBOMs with malformed/poisoned `locations[].layerID`; every case lands in `Unknown(reason="sbom_layer_attribution_absent")` or a typed-attested result. **No `KeyError`, no silent `app_direct`.**"
- §Edge cases row #1 (line 1362) — poisoned SBOM manifests-as, detected-by, system-behavior triple.
- §Adversarial tests (line 1444) — the exemplar row Phase 7 promises.

**Phase ADRs implicated:**
- ADR-0004 — primitive home; the fence proves consumers respect the boundary.
- ADR-0009 — Phase 7 byte-edit allowlist. Adding `_KNOWN_SBOM_FIELDS` to `syft_reader.py` is a S1-05-touched additive edit that needs allowlist coverage; verify at execution time.

**CLAUDE.md commitments implicated:**
- **"Fence-enforced structural defenses live under `tests/fence/`"** — this story ships one.
- Rule 8 (Read before you write) — `syft_reader.py` already declares `_KNOWN_LOCATION_FIELDS` + `_KNOWN_ARTIFACT_FIELDS` catalogs explicitly labeled "S4-04 fence source of truth"; the story's hardcoded parallel allowlist is drift-by-design.
- Rule 12 (fail loud) — the shipped `test_no_any_in_provenance_surface.py` floor-guards for silent-green (files-empty case); this story's fence should mirror that discipline.
- **Extension by addition** — the walker itself should live in a helper library the fence + its unit tests both consume; adding a new SBOM-consumer module = one row in a target-list, not a new fence file.

**Precedent (codebase shape to mirror):**
- `tests/fence/test_no_any_in_provenance_surface.py` — the *canonical* Phase-7 AST-walk fence: walker lives in a shared library (`codegenie._phase3_fence.walk_any_annotations`); the fence file imports it, applies it to `PHASE7_ROOTS`, and holds a `_SHAPE_MATRIX` parametrized negative-and-positive test that proves the walker catches each pattern shape. No `_meta.py`, no planted-fixture file, no self-referential import from the fence module.
- `tests/fence/test_vuln_provenance_no_model_construct.py` — simpler AST-walk-fence precedent under `tests/fence/` (parametrized-per-file, `_find_model_construct_calls` helper defined in-module). Second-cleanest shape.
- `src/codegenie/primitives/vuln_provenance/syft_reader.py` lines 41–49 — `_KNOWN_LOCATION_FIELDS` + `_KNOWN_ARTIFACT_FIELDS` catalogs, explicitly documented as "S4-04 fence source of truth" — the single-source-of-truth the story's hardcoded allowlist duplicates.
- `tests/property/vuln_provenance/_strategies.py` — the shared Hypothesis-strategies helper module (Phase 7 S2-05); the correct home for a new `_SBOM_TAMPERING_STRATEGIES` module + a `SbomShape(StrEnum)` completeness anchor.

## Critics — findings

### Critic A — Coverage

| Tag | Finding | Severity | Disposition |
|---|---|---|---|
| F-COV-1 | AC-3 lists three allowed `Unknown.reason` values (`"sbom_layer_attribution_absent"`, `"base_image_probe_absent"`, `"base_image_not_distroless"`). But `assemble_provenance` (shipped `assembly.py`) can produce `Unknown(reason="no_adapter_resolved")` when both layer walks return `Unknown` — which is the *default* case for a poisoned SBOM feeding an adapter chain of just Alpine + Distroless without a real image manifest match. Also `"adapter_error"` when an adapter raises `ProvenanceError`. A mutant that returns `Unknown(reason="no_adapter_resolved")` on every draw would pass AC-3 (correctly) but a mutant that produces `Unknown(reason="build_failed")` (a nonsensical reason for this call path) would ALSO be flagged as valid. The allow-set is too narrow to catch composition-loss regressions and too wide to catch reason-value drift. | HARDEN | AC-3 rewritten to explicitly enumerate the full closed allow-set of `Unknown.reason` values that `assemble_provenance` can produce on a poisoned-SBOM call: `{"sbom_layer_attribution_absent", "base_image_probe_absent", "base_image_not_distroless", "base_image_not_alpine", "no_adapter_resolved", "adapter_error"}`. Explicitly forbids `{"build_failed", "dockerfile_parse_failed", "base_image_already_distroless"}` (those reasons come from other code paths and reaching them on a poisoned SBOM would indicate a defect). |
| F-COV-2 | No AC covers `image_ref=None` in the adversarial input. The adapter `attribute()` signature is `(cve_id, package_id, image_ref: ImageRef | None, sbom)`; a hostile SBOM combined with `image_ref=None` is a legitimate adversarial input the property test should exercise. | HARDEN | AC-2 Shape catalog extended with **Shape G (`image_ref=None`)** — same six poisoned-SBOM shapes paired with `image_ref=None`; asserts the return lands in the AC-3 allow-set (specifically `"base_image_probe_absent"` or `"no_adapter_resolved"`). |
| F-COV-3 | AC-2 says "≥ 20 cases per shape ≥ 120 total". Nothing enforces that every shape actually gets drawn — a bug in the strategy composition (e.g., one `st.one_of` arm mis-typed) could silently draw only Shapes A–E. AC-6's `hypothesis.event(...)` tagging enables *detection* of skew but doesn't *enforce* balance. | HARDEN | AC-6 tightened — the property test asserts (via a `finalize`-style call collecting `hypothesis.stats.event_counts`) that every `SbomShape` enum member was drawn at least once. Silent-skip becomes silent-fail. |

### Critic B — Test Quality

| Tag | Finding | Severity | Disposition |
|---|---|---|---|
| F-TQ-1 | AC-4 wraps `assemble_provenance(...)` in `try/except Exception as e: pytest.fail(...)`. Two problems: (a) the traceback the operator sees is `pytest.fail`'s call site, not the raw exception's origin — worse debugging signal than letting the exception propagate directly (Hypothesis's own falsifying-example reporter surfaces the raw traceback naturally); (b) `except Exception` is broad enough to swallow diagnostic `AssertionError`s from *inside* the callee if the callee ever grows a defensive assertion — a silent-swallow smell. | HARDEN | AC-4 rewritten: **remove the try/except wrapper entirely**; a raised exception is Hypothesis's own falsifying signal (which prints the shrunk-example plus native traceback). The AC's assertion becomes "`assemble_provenance` returns a `Provenance` variant satisfying AC-3; if it raises **any** exception, Hypothesis reports the falsifying example and the test fails with the raw traceback." Mirrors Rule 12 (fail loud) — pytest's own error surface is louder than a wrapped `pytest.fail`. |
| F-TQ-2 | The fence's `_meta.py` + `_ignore_sbom_drift_fixtures/bad_adapter.py` design is a **fence-with-planted-file** pattern that reads a scratch fixture file to prove the walker works. The shipped Phase-7 fence precedent (`tests/fence/test_no_any_in_provenance_surface.py`) uses a **shared-library-walker + `_SHAPE_MATRIX` parametrized-snippets** pattern that is (a) faster (no filesystem read), (b) easier to extend (one row per new shape), (c) more mutation-resistant (each shape independently asserted), and (d) does not create a scratch-file dumping-ground under `tests/fence/`. | BLOCK-RESOLVED | AC-11 rewritten to require: the walker lives in a helper library at `tests/fence/_lib/sbom_access_audit.py` (new module — shared by the fence file + a walker-unit-test file); the fence file (`test_alpine_adapter_reads_known_fields_only.py`) imports `find_violations(source: str, path: Path) -> tuple[Violation, ...]` from the helper; a `_SHAPE_MATRIX: Final[tuple[tuple[str, bool], ...]]` in the fence file parametrizes positive+negative snippets and asserts the walker catches each pattern shape. **Removed:** `_meta.py`, `_ignore_sbom_drift_fixtures/`, `bad_adapter.py` (three files eliminated). |
| F-TQ-3 | AC-14 says "wall-clock ≤ 30 seconds"; nothing enforces this at CI time. A future Hypothesis-strategy regression that widens draw complexity 10× would silently blow the budget. | HARDEN | AC-14 augmented: add `@pytest.mark.timeout(60)` (2× the target as a hard ceiling) — CI-enforced. The 30-second soft target stays in the AC prose as the design intent. |
| F-TQ-4 | AC-2 Shape D uses `hypothesis.assume(drawn_hex != known_hex)`. `assume(...)` is rejection sampling — Hypothesis retries the draw when the assumption fails, and if the strategy is narrow enough the retries dominate wall-clock (or Hypothesis reports "flaky: too many discarded examples"). Deterministic construction (a strategy that guarantees a colliding-free draw by construction) is faster and more auditable. | HARDEN | AC-2 Shape D rewritten to specify the deterministic strategy: `st.text(alphabet="0123456789abcdef", min_size=64, max_size=64).map(lambda h: f"sha256:{h}")` combined with a fixture manifest whose `layers = ()` (empty tuple by construction; every drawn hex is guaranteed-not-in-manifest). Optional stricter mode: manifest holds one specific `"sha256:" + "0" * 64` layer and the strategy draws hex with `st.characters(whitelist_characters="123456789abcdef")` for the first character — no `assume` needed. |
| F-TQ-5 | AC-5 says "Determinism property: same drawn SBOM twice returns equal `Provenance`". The phrasing conflates two things: (a) `assemble_provenance` is a pure function → same input → equal output (functional determinism, worth asserting), and (b) Hypothesis is deterministic given a fixed seed (a Hypothesis property, not this test's). AC-5's "pins the seed via `@hypothesis.settings(...)`" is confusing — `@settings(...)` doesn't pin the seed unless `derandomize=True` is set, which the AC doesn't require. | HARDEN | AC-5 rewritten as a pure functional-determinism assertion: "for every drawn SBOM, `assemble_provenance(...)` is called *twice* with byte-identical inputs and the two returned `Provenance` instances compare equal (Pydantic `__eq__`)." Removed all seed-related language. This is the property `test_idempotence.py` already establishes for non-poisoned inputs — this AC extends the property to the poisoned-input surface. |

### Critic D — Design Patterns

| Tag | Finding | Severity | Disposition |
|---|---|---|---|
| F-DP-1 | The hardcoded fence allowlist duplicates a primitive-owned catalog — a **single-source-of-truth** violation. This is the same class of finding as F-CON-2 but framed as design pattern: the primitive is the source of truth for its own known fields; consumers (the fence) should **read** the catalog, not **mirror** it. Registry / read-through pattern. | (subsumed by F-CON-2 / F-DP-1 shared resolution) | AC-8 imports the catalogs; AC-8a mandates the missing `_KNOWN_SBOM_FIELDS`. Notes-for-implementer names the pattern explicitly ("The fence is a **consumer** of the primitive's declared field catalogs; adding a new field to the primitive must be a one-line addition to one `_KNOWN_*_FIELDS` frozenset that the fence picks up automatically. No fence-file edit required for typed-field additions."). |
| F-DP-2 | The walker as a private symbol inside the fence file, imported by `_meta.py` via `from test_alpine_adapter_reads_known_fields_only import _walk_attribute_accesses`, mixes test-collection and library-import concerns. pytest may or may not import the fence module depending on collection order; test-to-test imports are a fragile smell. Extracting the walker to a helper library at `tests/fence/_lib/sbom_access_audit.py` is a **hexagonal / ports-and-adapters** shape: the walker is the *port* (pure AST logic), the fence file is the *adapter* (wires the port to specific target files and assertions). | (subsumed by F-TQ-2's resolution) | Walker at `tests/fence/_lib/sbom_access_audit.py`; both the fence file and the `_SHAPE_MATRIX` parametrized tests import from it. Two-line `tests/fence/_lib/__init__.py` marker file. |
| F-DP-3 | The story's fence walks a **hardcoded three-file target list** (`alpine_provenance.py`, `distroless_provenance.py`, `sbom_verifier.py`). If a future story adds `npm_provenance.py` (Phase 3 already ships it under the vulnerability-remediation plugin — verified this touches `SyftSbom`), or if Phase 7 adds a fourth base-image adapter (debian, rhel), the fence must be edited. Two options: (a) accept the hardcode as Rule-of-three-not-yet-reached (three files today) and add a Notes-for-implementer entry naming the natural hoist point when a fourth SBOM-consuming module lands, or (b) upgrade to a dynamic target-list (glob `**/{provenance,sbom_verifier}*.py` under specific roots). Rule 2 says (a). | HARDEN | AC-10 keeps the three-file hardcoded target list (Rule 2 — three concrete consumers is at the rule-of-three threshold; adding globbing now is premature abstraction until a fourth arrives). Added a `_SBOM_CONSUMER_TARGETS: Final[tuple[Path, ...]]` module-level constant so the target list is *named* (single point of edit; the fence body iterates the tuple, no repeated Path literals). Notes-for-implementer names the natural hoist point (fourth consumer → auto-discovery over `_SBOM_CONSUMER_ROOTS`). |
| F-DP-4 | AC-2's Shape catalog (A–F) is expressed as hardcoded prose strings inside the AC body. There is no typed enum for the shape set, so AC-6's `hypothesis.event("shape:A_no_attribution")` uses free-form strings that can drift between the strategy code and the assertion. **Newtype / sum-type discipline:** a `class SbomShape(StrEnum)` in the shared strategies module gives the strategy + event-tag + completeness assertion (F-COV-3) one canonical source. | HARDEN | New AC-2b: define `class SbomShape(StrEnum)` in the shared strategies module (`tests/property/vuln_provenance/_sbom_tampering_strategies.py`) with members `A_NO_ATTRIBUTION, B_MALFORMED_LAYER_ID, C_TRUNCATED_LAYER_ID, D_FABRICATED_LAYER_ID, E_POISONED_ARTIFACT_EXTRA, F_POISONED_SBOM_EXTRA, G_NULL_IMAGE_REF`. AC-2's per-shape strategies iterate `SbomShape`; AC-6 asserts every enum member appears in `hypothesis.stats.event_counts`. Shape-set-completeness is now a compile/collection-time assertion, not a manual eyeball at draw-stats. |
| F-DP-5 | The `Violation` type mentioned in the Implementation outline is under-specified ("frozen Pydantic record"). A typed shape is a stronger contract: `class Violation(_Frozen): file: Path; line: int; pattern_kind: Literal["extra_attr", "descriptor_attr", "dict_bag", "vars_call", "pydantic_extra_attr"]; snippet: str`. Enables downstream categorization if the fence ever grows richer output. | HARDEN | AC-11 rewritten to pin the `Violation` shape: `class Violation(NamedTuple): file: Path; line: int; kind: str; snippet: str` (NamedTuple keeps it stdlib-only per AC-17; kind is a `Literal` union locked at the helper's public surface). Simpler than Pydantic; sufficient for the current use. If a downstream consumer needs richer categorization, upgrade to a frozen Pydantic record; documented as a follow-on. |
| F-DP-6 | The story's two orthogonal defenses (static fence + dynamic property test) is textbook **defense in depth** — the correct pattern for a load-bearing correctness invariant. The story's Notes-for-implementer names this discipline explicitly. | (positive — no action) | Preserved as-is. |

## Verdict

**HARDENED.** Three block-severity structural issues resolved (F-CON-2 / F-DP-1 single-source-of-truth; F-CON-1 factual mismatch on `SyftSbom.descriptor`; F-CON-6 execution precondition on S4-01/S4-02/S4-03 shipping); five harden-severity tightening edits folded in (F-COV-1 tightened reason allow-set; F-COV-2 added `image_ref=None` shape; F-COV-3 shape-completeness assertion; F-TQ-2/F-CON-4 walker-helper-module refactor mirroring `test_no_any_in_provenance_surface.py`; F-DP-4 `SbomShape` enum for completeness) plus one nit (F-TQ-1 exception-loud-fail discipline). No goal or scope change. Story is executor-ready **once its Pre-flight AC-0 passes** (S4-01/S4-02/S4-03 must be `Done`, not just `HARDENED`).

The story now:

- Consumes the primitive's own field catalogs rather than mirroring them (Registry / read-through pattern; production ADR-0039 spirit).
- Follows the canonical Phase-7 fence shape (`test_no_any_in_provenance_surface.py`) — walker in a helper library, fence file consumes it, `_SHAPE_MATRIX` proves the walker.
- Names the closed set of `Unknown.reason` values `assemble_provenance` can produce on this call path — mutation-resistant at both ends.
- Types the SBOM-shape set as an enum so completeness is a first-class assertion, not a manual eyeball.
- Uses deterministic construction (Shape D) instead of rejection sampling (`assume(...)`).
- Guards against silent-green via a pre-flight AC that halts execution if the referenced adapter files don't exist yet.
