# Phase 7 — Cross-story lessons learned

Append-only ledger of lessons that apply to *other* Phase 7 stories. One
bullet per lesson; cite the originating story; keep it short.

## 2026-05-19 — S1-01 (newtype identifiers)

- **Python 3.13 yields bare strings (not `ForwardRef`) from `typing.get_args(tuple["X", "Y"])`.** Tests that introspect `TypeAlias` forward references must accept both shapes (`isinstance(a, ForwardRef) else a` to extract the name).
- **TYPE_CHECKING-guarded imports from not-yet-landed modules need an `[[tool.mypy.overrides]]` entry** with `ignore_missing_imports = true`. The override should name the originating story and be removed when the target module lands. Phase 1's `networkx`, S3-04's `pyarn`, and S1-01's `codegenie.primitives.vuln_provenance.registry` are the established pattern.
- **`_NEWTYPE_REGISTRY` is for `NewType`s only — `TypeAlias` rows do NOT belong.** `__all__` is the superset; the registry tests must subtract `TypeAlias` names before asserting key-equality.
- **Phase 7 `_NEWTYPE_REGISTRY` entries cite ADR-0004 / ADR-0006**, not Phase 3's ADR-0010. The Phase 3 `test_newtype_registry_matches_all` was extended (additively) to branch the ADR-citation check on Phase membership.
- **Phase 7 `Ecosystem` Enum (S2-01) collides at the symbol level with the Phase 3 `Ecosystem` Literal (`codegenie.types.identifiers`).** This is intentional — different modules, different membership, different responsibility. The Phase 7 alias chain uses underscored `_PhVnEcosystem` / `_PhVnLayer` to keep the symbols distinct; AC-11 sentinel test fails loud on accidental cross-module imports.

## 2026-05-19 — S1-02 (DistroPackage + enums + fences)

- **`_Frozen` is new in Phase 7, NOT inherited from Phase 3.** Phase 3's `transforms/outcomes.py` uses repeated inline `model_config = ConfigDict(frozen=True, extra="forbid")`. S1-02 introduces the shared `_Frozen(BaseModel)` base under `primitives/vuln_provenance/types.py` and the AC-11 AST-walk fence (`tests/fence/test_vuln_provenance_frozen_base.py`) locks it scoped to `primitives/vuln_provenance/`. Future stories adding `BaseModel` subclasses in this subpackage MUST inherit `_Frozen` or amend ADR-0004.
- **`Field(min_length=1)` alone admits `" "` and `"\t"` (length 1).** Use a `field_validator` enforcing `value.strip() == value and value != ""` on every string field that downstream consumers index by — `(distro, name, version)` tuples poison silently under whitespace contamination. Sibling primitive records should mirror the pattern.
- **`model_construct(...)` is forbidden under `primitives/vuln_provenance/`** by the AC-14 fence (`tests/fence/test_vuln_provenance_no_model_construct.py`). It skips validation, which would let an adapter admit `DistroPackage(distro="centos", ...)` and poison the event log. Use the validating constructor; if a test or fixture needs the bypass, build the fixture outside the primitive tree.
- **`StrEnum` (Python 3.11+) is the codebase precedent** (`transforms/sandbox/_seccomp.py`), not the older `(str, Enum)` shape. Ruff UP042 enforces this. The static contract is identical — `mypy --strict` rejects a raw `str` where the enum is annotated either way; the AC-15 negative test pins this.
- **The kernel-frozen fence (`tests/fence/test_kernel_frozen.py`) admits `primitives/` as an additive top-level package** (S1-02 added `"primitives"` to `_TOP_LEVEL_PHASE3_PACKAGES` alongside `plugins`, `transforms`, `vuln_index`). Future Phase 7 stories that touch `src/codegenie/primitives/vuln_provenance/*` do NOT need per-file allowlist entries — the directory is admitted at the top level.
- **`__init__.py.__all__` is locked by `test_types_dunder_all.py`** to exactly `["AdapterConfidence", "DistroPackage", "UnknownReason"]` today. S1-03 grows the tuple additively (`AppDirect`, `AppKind`, ..., `Unknown`) and updates `_EXPECTED_PUBLIC_ALL` in the test. Sort-order: ASCII (`_` > capital letters).
- **JSON round-trip is the minimum AC for every nested record in `Provenance`.** AC-12's `model_dump_json` → `model_validate_json` → equals pattern catches silent serialization drift before downstream phases consume the event log. Mirror for every variant S1-03 lands.

## 2026-05-19 — S1-05 (SyftSbom Pydantic reader)

- **Phase 7's `_Frozen` fence has a documented carve-out path.** `tests/fence/test_vuln_provenance_frozen_base.py` now carries a `_DELIBERATE_EXTRA_ALLOW_RECORDS: Final[frozenset[tuple[str, str]]]` allowlist keyed on `(filename, class_name)`. The S1-05 syft models are the *only* admitted entries today; widening it requires an ADR-0004 amendment. A future story that introduces another `extra="allow"` model in this subpackage either inherits `_Frozen` or registers an explicit allowlist entry with the documented rationale.
- **Carve-outs need intent-pinning tests.** `test_s1_05_carve_out_actually_carries_extra_allow` AST-walks each admitted class and asserts it literally declares `ConfigDict(extra="allow")`. A maintainer who removes `extra="allow"` (the documented reason for the carve-out) without removing the carve-out entry trips the fence. Mirror this pattern for every future structural allowlist — the test verifies *why*, not just *that*, the carve-out exists (Rule 9).
- **`extra="allow"` is the single Phase 7 primitive-tree exception to `extra="forbid"`** — it lives on `SyftSbom`, `SyftArtifact`, `SyftLocation` because the upstream Anchore syft schema evolves. Defense is at the *consumer boundary* (S4-04's AST fence over adapter source — pins adapters to read only the fields in `syft_reader._KNOWN_*_FIELDS`). Do not introduce additional `extra="allow"` models in this subpackage without the matching consumer-side defense.
- **`_KNOWN_*_FIELDS` are module-private, `Final[frozenset[str]]`, and the source of truth for the S4-04 fence.** They are NOT re-exported via `__all__`; downstream fences import them via direct-module import. Growing the catalog is a two-line change here + a one-line update in the fence test.
- **`model_construct()` is forbidden under `primitives/vuln_provenance/` by *two* fences now** — the existing AC-14 fence (`test_vuln_provenance_no_model_construct.py`, S1-02) at the subpackage scope, and the per-file AC-8.5 fence inside `test_syft_reader_module_purity.py` (S1-05) on the deserialization surface specifically. Defense-in-depth: the syft reader is the most likely attractor for a "performance shortcut" because it parses untrusted JSON; the per-file fence makes that violation a one-line `grep` job.
- **`from __future__ import annotations` + `TYPE_CHECKING`-guarded placeholder for forward references** survives the dependency landing. S1-04's `protocols.py` carries a `class SyftSbom: ...` placeholder under `if TYPE_CHECKING:` and uses the bare string `"SyftSbom"` in the runtime annotation. S1-05's real model does NOT require touching `protocols.py` — the existing forward-reference test (`test_attribute_sbom_param_is_forward_reference_today`) keeps passing because `get_annotations(..., eval_str=False)` returns the unevaluated string. Tightening to `get_type_hints(...) is SyftSbom` is left for a follow-up when an adapter actually imports it.

## 2026-05-19 — S1-06 (Phase 7 LLM-SDK + no-`Any` fences)

- **Reuse `walk_any_annotations` directly from `_phase3_fence` — do not extract.** The walker is pure `(src, path) -> list[Violation]` and root-agnostic. Phase 7's extension was one new `PHASE7_ROOTS` tuple + a thin `_scan_phase7_surface()` wrapper local to the test module, no fork of the visitor or the `Violation` dataclass. Mutation-resistance is preserved because a regression in `walk_any_annotations` kills both Phase 3 AND Phase 7 fences simultaneously. The walker module name (`_phase3_fence`) is now a slight misnomer for a Phase-7 consumer; deferring the rename until a third surface appears (surgical-change discipline trumps cosmetic consistency).
- **Pin `include_external_packages = true` per-contract**, not only at the global `[tool.importlinter]` level. The global setting works for import-linter operationally, but the shape-pin test reads the contract dict and asserts the knob there — pinning per-contract makes the contract self-describing and gives the test a single source of truth. Story spec literally encoded the knob; mirror the spec.
- **Three-out-of-three planted-violation evidence is cheap and proves the gates are real.** Sub-second per gate. Each plant + observe-failure + remove cycle is recorded in the `_attempts` log with the literal failure message, so a future maintainer can reproduce on demand. The Phase 3 S1-05 validation precedent flagged 1-out-of-3 as a block-tier weakness; 3-out-of-3 is the baseline going forward.
- **The fence's fail-loud-on-ImportError path is a feature, not a workaround.** In dev environments where the forbidden SDK is not installed, planted `import anthropic` surfaces as `ImportError → AssertionError` (the scanner wraps the import). The operator sees the planted module by name and can act. The `sys.modules ∩ FORBIDDEN_LLM_SDKS` path is covered by the parametrized fake-SDK shim tests. One scanner, two failure modes, both useful.

## 2026-05-19 — S2-02 (AdapterFactory + DI kwarg vocabulary)

- **The no-LLM fence's snapshot/restore must repair the parent-package attribute, not just `sys.modules`.** The planted-positive tests in `test_phase7_no_llm.py` / `test_no_llm_in_transforms.py` pop `vuln_provenance.*` (or `plugins.*`) from `sys.modules` and `importlib.import_module` them fresh. `import_module` rebinds each submodule as an attribute on its *parent package*; restoring `sys.modules` alone leaves the parent attribute pointing at the fresh module. A later `from codegenie.primitives import vuln_provenance` then resolves to fresh `Layer`/`Ecosystem` classes, breaking `is`-identity against names captured at collection time — a CI-only failure (test ordering). Fix: `setattr(parent, child, original)` alongside the `sys.modules` restore. Applies to any future fence that pops + re-imports a package subtree.
- **DI kwarg types that are not-yet-landed should be `object`, not a guessed concrete type.** S2-02's `DefaultAdapterFactory` types `sbom_reader` / `image_manifest_cache` / `logger` as `object | None` — `SbomReader`/`ImageManifestCache` are not named types yet (S1-05 ships SBOM *models*, ADR-0004 ships an `image_digest_resolver` *callable*), and the codebase logs via `structlog`, not stdlib `logging`. A pure pass-through (the factory never invokes the deps) has no business over-constraining the type; `mypy --strict` enforces the real types at each adapter's own `__init__`. S3-02+ adapters should type their `__init__` deps concretely.
- **Make the closed vocabulary the iteration domain, not a secondary `and` check.** `DefaultAdapterFactory.__call__` builds the injected kwargs with `{name: available[name] for name in _DI_KWARGS if name in parameters}`. Iterating `_DI_KWARGS` means a name outside the closed set is structurally unreachable — strictly stronger Open/Closed than three `if "x" in declared and "x" in _DI_KWARGS` blocks. Adding a DI kwarg touches `_DI_KWARGS` + the constructor/`available` mapping only.
- **mypy-clean factory tests: record `__init__` args into a closure dict; do not read attributes off the factory return.** The factory returns `VulnProvenanceAdapter` (a Protocol with only `attribute`/`confidence`); poking `.sbom_reader` on it fails `mypy --strict`. Fixture adapters write what they received into a `dict[str, object]` closure variable; assertions read the dict. Bonus: `set(received)` then catches a "passes extra kwargs" mutant. Fixture `attribute`/`confidence` stubs are typed `-> Any` so the class structurally satisfies `type[VulnProvenanceAdapter]` (mirrors `test_registry.py`).

## 2026-05-19 — S2-03 (`_ADAPTER_DISPATCH_ORDER` + intra-layer iteration)

- **Re-exporting a public name from `vuln_provenance/__init__.py` *requires* updating `_EXPECTED_PUBLIC_ALL` in `test_types_dunder_all.py`.** That tuple is a byte-exact pin of the package `__all__`; growing `__init__.py` without growing the pin is a guaranteed `make test` failure. This is a required consequence of the change, not a discretionary touch — S2-01, S2-02, S2-03 all edited this fence for the identical reason. Treat the dunder-all test as part of the `__init__.py` change-set.
- **Tooling note: `lint-imports` / `mypy` / `make {lint-imports,typecheck}` fail locally when `.venv/bin` is not on `PATH`.** The `test_lint_imports_canary.py` tests resolve the console script via `shutil.which` and `AssertionError` if absent. Run gates as `.venv/bin/<tool>` directly, or prefix `PATH="$PWD/.venv/bin:$PATH"`. CI activates the venv so these pass there — a local-only red, not a code defect.
- **Module-private dispatch data is reached via the module path, not re-exported.** `_ADAPTER_DISPATCH_ORDER` (leading underscore) stays out of `__init__.py`; S2-04 imports it as `from ...vuln_provenance import assembly as _assembly_mod`. Only the public helper `iter_adapters_for_layer_set` joins the package surface. Mirrors S2-01's `_REGISTRY`.

## 2026-05-19 — S2-04 (`assemble_provenance` composition free function)

- **`mypy --strict` cannot prove tuple-pattern `match` exhaustiveness with class patterns.** `match (app_result, base_result)` with four `case (AppDirect()|... as app, None)`-style arms leaves `case _: assert_never(...)` failing — mypy does not eliminate matched tuple shapes from the subject type. The fix that works: make the **last** arm a pure-capture `case (app, base)` (an irrefutable 2-tuple pattern mypy *does* see as exhausting the subject), so `case _` narrows to `Never`. The two captures in that arm then need `cast(...)` — mypy will not cross-narrow them out of `| None`. Class patterns in the *earlier* arms still narrow their captures correctly for `return`. Any future `match` over a tuple of optionals (S2-05's property tests included) should expect this shape.
- **S1-05's deferred `protocols.py` placeholder swap landed in S2-04.** S1-04 left `class SyftSbom: ...` as a `TYPE_CHECKING` placeholder; S1-05 deliberately deferred replacing it "until an adapter actually imports it" (S1-05 lesson above). `assemble_provenance` is the first code to call `adapter.attribute(..., sbom)`, so S2-04 completed the swap to the real `TYPE_CHECKING`-guarded import. The import stays guarded — the runtime annotation is still the bare string `"SyftSbom"`, so the AC-6 forward-reference test is unchanged. `test_protocols_module_purity.py`'s allowlist gained the `syft_reader` entry. Adapters S3-02 / S4-02 / S4-03 can now rely on `protocols.SyftSbom` being the real model.

## 2026-05-20 — S3-01 (npm-adapter contract test, red-first)

- **A stale git worktree can hijack the venv's editable `codegenie` install — verify `codegenie.__file__` before trusting a red `make check`.** S3-01's first `make check` reported 29 failures across `tests/fence/`, `tests/golden/`, `tests/unit/types/`. Root cause: `import codegenie` resolved to `.claude/worktrees/<name>/src/codegenie` (an in-flight PR's worktree), not the main repo's `src/codegenie`. The worktree predated master's types↔probes cold-start fix, so the suite tested stale source. Diagnosis: `.venv/bin/python -c "import codegenie; print(codegenie.__file__)"`. Fix: `.venv/bin/pip install -e . --no-deps` from the main repo root re-points the editable finder. Whenever `.claude/worktrees/` exists, check `codegenie.__file__` first — a red gate may be testing the wrong tree, not a code defect.
- **Red-first contract tests put `xfail(strict=True)` on the not-yet-satisfiable scenarios only — never on the red-state canary.** The canary asserts the *current* (no-adapter) outcome and must PASS so CI stays green; the future scenarios are `xfail(strict=True)` so a wrong-reason pass later breaks the strict gate. Marking the canary `xfail(strict=True)` would XPASS → strict failure immediately. S3-01's AC-10 prose garbled this; the self-consistent reading (AC-9 + Implementation-outline "1 passed, 3 xfailed" + the TDD plan) is the contract.
- **`ImageRef` is a bare `NewType`, not a smart-constructor class.** Several Phase 7 stories' ACs reference `ImageRef.parse(...).unwrap()`; that API does not exist — S1-01 shipped `ImageRef = NewType("ImageRef", str)`. Construct directly: `ImageRef("...")`. Code (tests or adapters) that needs ref *validation* must add its own parser; the newtype alone is an unchecked alias.
