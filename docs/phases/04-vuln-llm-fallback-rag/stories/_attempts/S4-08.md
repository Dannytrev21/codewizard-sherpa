### What didn't work the first time

1. **mypy --strict + `**_SHARED_PARTITION` typing.** The first cut hoisted `(task_class, language, build_system)` into a `Final[dict[str, str]]` and unpacked it into `make_solved_example(...)`. mypy --strict (correctly) refused — `build_system` is `Literal[...]`, not `str`. Fix: dropped the `_SHARED_PARTITION` indirection entirely and relied on `make_solved_example`'s own defaults (which already match the same-partition triple required by AC-1). A header comment documents the choice. Rule 11 — match the existing convention (`tests/integration/test_phase4_store_contention_30s.py` and `tests/integration/test_phase4_provenance_orphan_emit.py` both use the fixture defaults directly).

2. **pytest fixture return type.** First cut typed `def store(...) -> ChromaPersistentStore` even though it `yield`s, which mypy --strict flagged as a missing return on the `close()` path. Fix: `-> Iterator[ChromaPersistentStore]` via `collections.abc.Iterator`. Mirrors `tests/conftest.py` fixture idioms.

### Design-pattern refactor decisions

- **Independent oracle (Hexagonal / Specification pattern)** — `_expected_head` is the test-side independent re-roll of BLAKE3 over canonical YAML bytes. It calls into the production helper `_compute_chain_head` so the chromadb collection identity is the only variable across orderings — every other step (canonical YAML, BLAKE3 ordering, error translation) is shared with the production write path. Mirrors S4-04 AC-5's "independent oracle" discipline rather than reimplementing the rolling logic byte-by-byte in the test.
- **Functional core / imperative shell** — `_expected_head` is pure (no fixture state); each test function is the imperative shell that drives `asyncio.gather` and asserts. Keeps the contention semantics legible.
- **No `cap_factory` helper, no `_slow_add` helper hoisted module-level** — per Rule 2 + S4-08 validator §`cap_factory` dropped. Three uses of `SolvedExampleWriteCapability(workflow_id=...)` is below the abstraction threshold; each gets the `# AC-2-test-only-direct-construction (S4-03 AC-2 boundary lift)` comment the S4-03 / S4-04 sibling style mandates.
- **Mock(wraps=…) over manual instrumentation (AC-9)** — `Mock(wraps=asyncio.to_thread)` gives us `call_count` and `call_args_list` for free while preserving the real `to_thread` semantics. Catches the wrong-target mutant (count stays, target changes) that a custom counter would not. `monkeypatch.setattr(asyncio, "to_thread", …)` patches the **module attribute** so `store.py`'s call-time `asyncio.to_thread` resolution picks up the wrapped callable.

### Lessons captured (cross-story)

To be appended to `_lessons.md`:

- **L-S408-1** — When a test file's same-partition records share the fixture's default `(task_class, language, build_system)` triple, don't introduce a `_SHARED_PARTITION` constant. The fixture defaults already encode the partition; a `dict[str, str]` indirection trips mypy --strict on Literal kwargs and the helper is below the Rule-2 abstraction threshold.
- **L-S408-2** — For `slow_add_a`-style lock-hijack coroutines, use raw `await store._add_lock.acquire()` (not `asyncio.wait_for`). `asyncio.Lock.acquire()` on a free lock returns *without suspending*, so the first-scheduled coroutine holds the lock before its first `await`, guaranteeing the second coroutine finds it held. A `wait_for` wrapper would race-condition the deterministic ordering this test depends on (Notes §5).
- **L-S408-3** — `asyncio.to_thread` regression guards belong in their **own** test, separate from contention/correctness tests. Folding the AC-9 mock into the happy-path test pollutes the lock contention semantics; the unwrap regression is a production-posture violation, not a contention-correctness one.
