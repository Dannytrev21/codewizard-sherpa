### Deferred / surfaced

* **AC-2 + AC-8a + AC-8b (BLOCKED on Phase-3 S7-01 + Phase-4 S7-01 follow-up).** Phase-3 S7-01 shipped the *plugin directory* (`subgraph/`, `adapters/`, `recipes/`) but did **not** ship the kernel `plugin.yaml` or an `api.py` module — the validation note ("only `PLUGINS.lock` + `__init__.py`") was outdated as of 2026-05-26 (directory now has subgraph/adapters/recipes), but `plugin.yaml` + `api.py` are still absent. Without `plugin.yaml`, there is no `requirements.optional` tuple to extend; without `api.py`, there is no construction site that loads `Phase4Config` and passes its values to `BandClassifier(high_floor=...)` + `LlmInvocationGuard(max_tokens=...)`. AC-8a's "runtime witness — drive a Similarity(0.86) candidate through the engine with `high_floor=0.99`" is therefore unreachable today. These three ACs land in a follow-up story (or this story's GREEN-complete pass) once Phase-3 S7-01's `plugin.yaml` + `api.py` exist.
* **AC-8c (Rule 7 conflict).** The validator's AC-8c text reads "asserts that `high_floor`, `degraded_floor`, `max_tokens`, `max_dollars`, `per_call_max_tokens` all have `default is inspect.Parameter.empty` (constructor requires the value)". Shipped S5-02 `BandClassifier` has `high_floor: float = 0.85, degraded_floor: float = 0.65`; shipped S2-05 `LlmInvocationGuard` has `max_tokens: int = _DEFAULT_MAX_TOKENS, max_dollars: Decimal = _DEFAULT_MAX_DOLLARS, per_call_max_tokens: int = _DEFAULT_PER_CALL_MAX_TOKENS`. Both defaults are exactly the "silent mask" attack vector AC-8c was meant to prevent. Honoring AC-8c verbatim today requires editing both shipped classes — outside S7-04's surgical scope (Rule 3). Resolution: ship AC-8c at the **Phase4Config sub-model level only** (every Pydantic field is required; no defaults could mask a missing YAML key). Surface the classifier/guard half as a Phase-5 follow-up. Surfaced per Global Rule 7 ("don't average two contradictory shapes").

### Design pattern reinforcements applied

* **Specification pattern (DP-03).** `_VALIDATORS: Final[tuple[Callable, ...]]` named-rule table — every business-rule rejection is one pure function, named for its rule. Past the 5-rule "factor it" threshold (we have 9 validators covering 12 named rules).
* **Pure / impure split (DP-06).** All 9 validators are pure functions of `Phase4Config`. The only impure code is the `safe_yaml.load` boundary call + `Path.stat` in `load_phase4_config`'s shell — mirrors `PluginManifest.from_yaml` exactly.
* **Result, never raise (DP-07).** `load_phase4_config` matches the kernel `PluginManifest.from_yaml` shape: returns `Result[Phase4Config, Phase4ConfigError]`; documented four-arm translation table for OSError → IoError, MalformedYAMLError → MalformedYaml, ValidationError → SchemaViolation, SizeCapExceeded → SizeCapExceeded.
* **Extension by addition (ADR-0043).** Kernel `PluginManifest` not edited. Phase 4 ships its own plugin-local config schema; the kernel registry-of-config-blocks is a Phase 7+ rule-of-three concern (vuln / distroless / hot-views / agentic are the future demand signal).
* **Single source of truth (F10).** All test fixtures import from `tests/_constants/phase4_defaults.py`; no embedded `0.85` / `250_000` / etc. literals in tests (verified by F4 mitigation — schema-rejection tests use `0.70`/`0.30` non-arch values).
