### Lessons (L-S404-*)

- **L-S404-1** — `_compute_chain_head` deliberately re-reads every record file on each `add()` (O(N) per add, O(N²) for full ingest). A running hasher held on `self` would be O(1) amortized but is hidden mutable state that can desync from disk and make `digest()` silently lie (Rule 12 violation). The stateless re-read keeps `digest()` a pure projection over disk and makes AC-12's "next `add()` recomputes from disk" recovery actually true. Revisit only if a perf test against the < 50 ms/add budget fails — never speculatively (story Notes §10).
- **L-S404-2** — `_Manifest` deliberately gets **no** `from_yaml` classmethod even though the public `SolvedExample` does (AC-10). The defensive inline parse in `_load_existing_record_ids` (via `_parse_manifest_or_raise`) is the only reader — translating every malformed case to `StoreCorrupted` with a diagnostic. A `_Manifest.from_yaml` would force every caller through the typed `pydantic.ValidationError` surface instead of the intended `StoreCorrupted` family. Only the public `SolvedExample.from_yaml` is named (S4-07's `codegenie rag rebuild` consumer).
- **L-S404-3** — `schema_version` is checked on the **raw** dict *before* `_Manifest.model_validate(...)` because `_Manifest` is `extra="forbid"` with `schema_version: Literal[1]` — without the pre-check, a hypothetical v2 manifest (new fields, `schema_version: 2`) would fail validation with a generic `ValidationError` instead of the intended `StoreCorrupted("unknown manifest schema_version")` diagnostic that names the upgrade path. The genuine Open/Closed seam (a table keyed on `schema_version`) arrives only when Phase 11 introduces v2 — not now (Rule 2; story Notes §8).
- **L-S404-4** — Hypothesis `st.builds(...)` against a Pydantic model with `NewType` + closed-`Literal` fields silently generates degenerate values (or fails construction outright on the nested `RecordProvenance` / `datetime` fields). Explicit per-field strategies (mirroring the repo's sum-type roundtrip precedent) are mandatory. The bound strategy chains (`_id_strategy = _hex_str(8).map(SolvedExampleId)` etc.) also keep the typing precise enough for `mypy --strict` to accept the composite without `cast()` except at the two closed-Literal sites (`signing_method`, `origin`).
