### Decisions of record

- **Tiebreak via `_lex_inverse` (negate codepoints), not via
  `min()` on a separate pass.** The story prose suggested a two-pass
  approach (filter to top-score, then `min()` by id); a single
  `max(..., key=lambda c: (c.score, _lex_inverse(c.record.id)))`
  achieves the same result in one pass. Equivalent behavior; tighter
  code.
- **`__post_init__` validation rejects NaN via `math.isnan`.** The
  story's listed `NaN` rejection cases (`pytest.raises(ValueError,
  match="...")`) only pass if NaN is detected explicitly — NaN fails
  every numeric comparison silently, so `0.0 <= NaN < hf <= 1.0`
  evaluates to `False` either way, but a clean NaN check up front is
  the load-bearing defense.
- **`isinstance(BandClassifier(...), ConfidenceClassifier)` works at
  runtime** because both are runtime-checkable Protocols. mypy
  --strict also accepts the structural conformance — the test
  asserts both.

### Refactor decisions

- **`_lex_inverse` is a free function, not a method.** No state, no
  per-class semantics — extracting it makes the `max(...)` key
  expression read cleanly. Composition over inheritance.
- **`classify_similarity` is the pure-function half of the
  Specification pattern; `BandClassifier.classify` is the imperative
  shell.** Same pattern as Phase-3 `LockfilePolicy.evaluate` (which
  the S5-02 story References block names as precedent).
