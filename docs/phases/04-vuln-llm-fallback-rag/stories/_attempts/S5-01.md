### Decisions of record

- **`CandidateSolvedExampleStore` is a narrow Protocol distinct from
  the full `SolvedExampleStore`.** The retriever depends only on
  `query_candidates(...)`. Narrowing the Protocol makes the dependency
  graph explicit and lets future read-only adapters skip implementing
  `add` / `digest` / `close`.
- **`SpanningChainLog` widened from 1 → 2 methods.** The chain-orphan
  event ships `spanning_log_head` for triage. Three options surfaced:
  (i) widen the Protocol; (ii) inject the head as a separate
  collaborator; (iii) drop the field. Option (i) is the smallest
  surface change — additive, doesn't break the existing
  `contains_chain_head`-only consumers, mirrors the S4-03
  candidate-read amendment pattern (extend the existing Protocol seam,
  don't fork it).
- **`RagMissEvent.reason` is a closed Literal.** Four values today
  (`empty_store`, `all_candidates_chain_orphan`,
  `all_candidates_model_mismatch`, `top1_below_floor`) — a Phase-5
  amendment adding a fifth requires editing this Literal AND the
  classifier (because `top1_below_floor` is the only one *the
  classifier* emits). Closed-set discipline mirrors S1-02's
  `LedgerStateKind`.
- **Retriever takes `query_builder: Callable[..., Query]` (not
  `Callable[[CveAdvisory, RepoContext], Query]`).** `CveAdvisory` /
  `RepoContext` are S7-02 plugin-resident types not yet shipped. The
  variadic shape keeps the kernel from depending on plugin types
  before they exist — testability win at the cost of slightly looser
  static typing. mypy --strict still verifies the dataclass + the
  retriever's body.
- **`query()` is `async`** because `store.query_candidates(...)` is
  `async` (the underlying chromadb call goes through `asyncio.to_thread`).
  The embedder is sync — called directly without `await`.
- **`Embedder.embed` is sync, not async** (the embedder.py Protocol
  has `def embed(...)`). The story's pseudocode showed
  `await self.embedder.embed(...)`, which would have been a TypeError
  at runtime. Matched the actual Protocol shape per Rule 11.

### Refactor decisions

- **Composition via free helpers** (`_new_event_id`, `_now_utc`,
  `_canonical_yaml_text`, `_digest_fenced`) instead of methods on the
  retriever. Each helper has one responsibility; the frozen dataclass
  stays method-light. Anti-refactor honored: no
  `BaseSolvedExampleRetriever` ABC, no `RetrievalPipeline` Command
  wrapper, no `EventEmitter` mixin.
- **`_emit_outcome_events` + `_emit_selected` extracted from `query()`**
  to keep the body readable. `query()` body is ~70 LOC after
  extraction; each helper does one thing.
