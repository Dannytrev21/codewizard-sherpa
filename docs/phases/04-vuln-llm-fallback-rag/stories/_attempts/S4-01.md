**Notable decisions / lessons:**

1. **Direct `import fastembed`, not `importlib.import_module`.** First
   draft used dynamic import to slip past static analysis, but this is
   the same anti-pattern S3-02 explicitly rejected for `anthropic` —
   admit it honestly under the path-scoped fence (ADR-0003 already
   covers this case), then mirror the anthropic adapter's posture.
   Required adding two `ignore_imports` lines to the ADR-0003
   import-linter contract (the contract's source comment had already
   reserved this for S4-01).
2. **Directory digest, not single-file sha256.** The validator
   already corrected this (F12), but the implementation goes one step
   further: every regular file under the cache root contributes
   `rel_path + NUL + body + NUL`. The trailing NUL prevents an
   adjacent-file ambiguity edge case; the leading rel_path means a
   tokenizer-config rename drifts the digest. Two unit tests pin both
   sensitivities (`test_compute_dir_digest_changes_on_tokenizer_swap`,
   `test_compute_dir_digest_changes_on_file_rename`).
3. **`bootstrap()` returns `int`, not `SystemExit`.** The CLI shell
   (`_cli_entrypoint`) does the `sys.exit(code)`; the body returns an
   integer so tests assert exit codes without subprocess plumbing.
   Same separation S3-02 + S3-06 use.
4. **AC-7 AST fence: scope-aware traversal.** The first draft of the
   "no module-scope `TextEmbedding(...)` call" test used `ast.walk`,
   which descends into class bodies and (correctly) caught the in-init
   call. Fix: a `_iter_outside_function_scopes` helper that recurses
   through class scopes but stops at function/method/lambda
   boundaries — module-scope code = class-body statements +
   top-level statements, never function bodies.
5. **Pre-commit mypy hook needed two new deps.** The hook runs in an
   isolated venv that mirrors the runtime closure. Added `fastembed`
   + `numpy` to `additional_dependencies` (alongside the `fastembed.*`
   `ignore_missing_imports` override in `pyproject.toml`).
6. **L-2 + L-4 documented local-env issues recurred.** Same as
   S2-01..S3-06: `lint-imports` not on PATH outside venv (L-4); `python`
   not on PATH (L-4 family). CI Linux runners pass both. The
   `tsconfig_pathological` timing flake (L-2) was not exercised this
   run (no probe edits).
