### Refactor decisions (design-pattern lens)

- **Protocol + adapter (Ports & Adapters).** The `SolvedExampleStore`
  `@runtime_checkable` Protocol is the port; `ChromaPersistentStore` is
  the adapter. Phase-11's pgvector adapter slots in behind the same
  Protocol — the load-bearing reason the four-method surface is fenced
  is so a future adapter author reads the contract from one place.
- **Capability pattern.** `SolvedExampleWriteCapability` is a frozen
  type-level marker that gates `add()`. S4-06 will mint via
  `_phase4_local_capability_mint`; the type itself lands here.
- **Newtype discipline.** Every domain identifier is a NewType
  (`SolvedExampleId`, `StoreDigest`, `WorkflowId`, `EmbeddingVector`);
  no raw `str` / `tuple` slipped past the boundary.
- **Functional core / imperative shell.** `_digest_record_ids`,
  `_collection_name`, `_metadata_from_example` are pure helpers; the
  impure shell lives in `add` / `query` / `_query_with_embedding`.
- **Markers-only exceptions.** `StoreWriteContention` carries
  `workflow_id`; `StoreClosed` / `StoreCorrupted` are pure markers.
- **Smart constructor — deferred to S4-06.** `SolvedExampleWriteCapability`
  has a public constructor in this story by design — S4-06 ships the
  sole-mint factory and the import-linter pin on its source list.

No anti-patterns introduced: no primitive-string identifiers, no
hidden state, no LLM SDK admission, no global mutable, no fence
violations.

### Lessons captured

- **L-S403-1 — chromadb's `to_thread(...)` types are invariant.**
  `collection.add(embeddings=[list(...)])` typechecks at *runtime* but
  `asyncio.to_thread` propagates the keyword-argument type into
  `mypy --strict` where `list[list[float]]` ≠
  `list[Sequence[float] | Sequence[int]]` (the chromadb-declared
  Sequence type is invariant inside the `list[...]`). Fix: declare the
  inner sequence as `Sequence[float]` and the outer list with the
  exact `list[Sequence[float] | Sequence[int]]` annotation. Same
  pattern recurs for `query_embeddings` on the read side.
- **L-S403-2 — pre-commit mypy hook stays in lockstep with admissions.**
  Adding `chromadb` as a path-scoped admission in S4-03 broke the
  isolated pre-commit mypy hook (it does not share the venv's
  installed packages). Mirror the admission in
  `.pre-commit-config.yaml` `additional_dependencies` alongside the
  S3-02 anthropic / S4-01 fastembed precedents. The S4-01 attempt log
  flagged the same lesson at a different package — codify it here as a
  cross-story checklist item for any future path-scoped admission.
- **L-S403-3 — chromadb 0.6.3 posthog telemetry warnings are stderr
  noise.** `Failed to send telemetry event ...: capture() takes 1
  positional argument but 3 were given` prints to stderr on every
  client/collection/query call. They do not fail tests and cannot be
  silenced via the documented `Settings(anonymized_telemetry=False)`
  in this chromadb release — known upstream issue with the posthog
  client signature. Do not paper over with a logging filter; surface
  to a future cleanup when chromadb is upgraded.
