### Refactor decisions

**Functional core / imperative shell** — strictly enforced by AC-23. The
five pure helpers carry every scan/redact arithmetic; `verify_cassette` is
the **only** function touching `Path` / `open` / `yaml`; `sanitize_*` are
thin adapters whose only non-pure step is `copy.deepcopy(input)` followed
by writeback through `_write_headers` (an imperative helper deliberately
**not** in the pure-helpers set — it mutates the already-deepcopy'd
target, which is the canonical imperative-shell shape).

**Single bytes catalog** — `_BODY_SECRET_PATTERNS` is one
`Final[tuple[re.Pattern[bytes], ...]]` of three rows. `str` header values
are encoded once at the boundary using `encode("utf-8", "surrogatepass")`
so they ride the same catalog — no parallel str/bytes tuple to keep in
sync. Validator §design-patterns flagged the alternative as the catalog
duplication that would later drift.

**Adapter containment for vcrpy types** — public sanitize_* are typed
`Any`-in / `Any`-out at the boundary so a vcrpy version bump (which keeps
adding sub-types) does not ripple into the contract. The actual storage
shape is detected at runtime via `isinstance(..., Mapping)` /
`isinstance(..., list/tuple)` (`_normalize_headers`). `_write_headers`
restores the original storage shape so vcrpy's `HeadersDict`
case-insensitive semantics survive the round-trip.

**`Violation` stays one model** — Rule 2: a test-only diagnostic consumed
by one CI scanner does not need a per-kind sum type yet. The
`@model_validator(mode="after")` closes the illegal-field-combination
hole with 8 lines and zero new types. If a later phase grows a fourth
violation kind with diverging fields, that is the rule-of-three trigger
to revisit.

**`passed` as derived property** — `@computed_field` + `@property` makes
`passed=True` alongside a non-empty `violations` structurally
unrepresentable. The silent-leak failure mode is impossible by
construction (AC-9 validator hardening).

### Surfaced conflicts (Rule 7)

1. **Story said "create `tests/conftest.py`" — the file already existed.**
   S3-03 had created it for `egress_test_loopback`. Resolution per Rule 7
   (pick the more recent / more tested): **modify** the existing file,
   preserve the S3-03 fixture, add `vcr_config` alongside. The story's
   AC-10 wording becomes a "modify"; the structural blast radius from
   AC-25 was unchanged because the conftest was already root-scoped.

2. **`re.Pattern[bytes]` cannot scan `str` header values directly.** AC-3
   pins bytes-typed patterns; AC-4(b) scans header *values* which are
   `str`. Resolution per the story's own §design-patterns guidance:
   encode each `str` value at the boundary using
   `encode("utf-8", "surrogatepass")`, scan with the one bytes catalog,
   decode back — one catalog, no parallel str/bytes tuple. The
   `surrogatepass` codec is the defensive choice for arbitrary byte
   sequences carried in a `str`-typed header.

3. **vcrpy's `HeadersDict` is a `MutableMapping` but NOT a `dict`
   subclass.** Discovered during integration TDD against
   `vcr.request.Request`: my first-pass `isinstance(headers, dict)` fell
   through to the stringify fallback, mangling the whole headers object
   into one `("repr", "")` row. Switched to `isinstance(headers, Mapping)`
   in `_normalize_headers` and `_write_headers`. **Captured as L-10 for
   future stories that work with third-party container types.**
