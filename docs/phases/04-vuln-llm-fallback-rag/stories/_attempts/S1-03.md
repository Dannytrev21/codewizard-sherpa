### Refactor decisions

Walked the design-patterns checklist again:

- **Tagged union + Smart constructor + Make illegal states unrepresentable** —
  `PlanOutcome` is closed via `Field(discriminator="kind")`; every variant is
  `frozen=True` + `extra="forbid"`; the `Refused.reason` Literal closes the
  refusal taxonomy (adding a fifth is an ADR amendment per ADR-0001
  §Reversibility).
- **Composition over union-widening** — the whole point of ADR-0004. The
  fence at `test_plan_outcome_no_recipe_outcome_widening.py` is the
  load-bearing assurance that future phases cannot silently widen Phase-3's
  `RecipeOutcome`. The fence message names ADR-0004 explicitly.
- **Loose coupling by digest** — `recipe_outcome_digest: BlobDigest`,
  not `recipe_outcome: RecipeOutcome`. Phase 4 stays Phase-4 even if
  Phase-3's serialization shape changes.
- **Single-source the config (F12)** — `_FROZEN_FORBID: Final[ConfigDict]`
  at module scope; matches S1-02's `fallback/` convention. Confirmed all
  four variants reference it.
- **Newtype discipline (production ADR-0033)** — `response_id: LeafResponseId`,
  `few_shot_ref: SolvedExampleId | None`, `recipe_outcome_digest: BlobDigest`.
  The attribute-read mypy-negative test enforces this statically.
- **Discriminator default values (F10)** — each `kind` field carries a default
  matching its tag, so the `test_kind_default_omittable_in_direct_construction`
  cases construct without `kind=` kwarg (mirrors arch §Data model line 734
  shape and S1-02's `plan_proposal.py`).
- **No imports of Phase 3 `RecipeOutcome`** into `plan_outcome.py` — only
  `BlobDigest` from `codegenie.types.identifiers`. The looseness is the
  whole point of ADR-0004's composition pattern.

No anti-patterns introduced: no primitive obsession (every domain field uses
its newtype); no anaemic data classes (every variant carries semantic
identity via `kind`); no hidden state; no `Any`.
