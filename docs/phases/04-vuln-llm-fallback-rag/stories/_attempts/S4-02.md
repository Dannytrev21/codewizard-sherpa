### Refactor decisions

Applied during the GREEN→REFACTOR pass; recorded for future readers
per the design-patterns lens:

1. **Decorator pattern** — `CachedEmbedder` wraps any `Embedder` without
   changing the Protocol shape (frozen at S4-01 AC-9). Composition
   happens at call-site (e.g., S5-01 retriever wiring), not inside
   `FastembedEmbedder.__init__`; each layer has one responsibility.
2. **Functional core / imperative shell** — `_blake3_hex`,
   `_encode_vector`, `_decode_row`, `_dedupe_preserve_order` are pure
   module-level helpers; `CachedEmbedder` is the imperative shell that
   owns the sqlite connection, lock, and side effects.
3. **Smart-constructor for `EmbeddingsCacheCorrupted`** — keyword-only
   `__init__` with `__slots__` mirrors the convention `EmbeddingsBootstrapRequired`
   / `EmbeddingModelMismatch` already use in this module (markers-only;
   diagnostic message rendered via `__str__`, not `args[0]`-folklore).
4. **Newtype passthrough** — all sqlite parameters are stringified
   (`str(BlobDigest)`) at the boundary so the column-typed `TEXT NOT NULL`
   storage stays primitive while the in-process type tracks the
   `BlobDigest` newtype identity (no primitive obsession in the body).
5. **Module-level `Final` schema constants** — `_SCHEMA`, `_PRAGMAS`,
   `_VECTOR_DIM`, `_VECTOR_BYTES`, `_VECTOR_DTYPE` are `Final` so a
   future contributor cannot reassign them at runtime; also pinned by
   the unit tests that assert PK shape and roundtrip byte counts.
6. **Two-tier corruption recovery** — file-level (rebuilds whole db,
   emits `cache_rebuilt_on_corruption`) vs. row-level (deletes one row,
   emits `embedding_cache_row_corrupted`). The two paths share no code;
   conflating them would lose the partial-recovery property.

**Patterns deferred (Rule 2 — Simplicity First):**

- **In-flight single-flight map for concurrent same-text misses.** Story
  §10 explicitly out-of-scope. The dual `inner.embed` calls produce
  byte-identical bytes that overwrite byte-identical bytes via
  `INSERT OR REPLACE` — idempotent, not wasteful enough to optimize
  ahead of a benchmark.
- **`clear()` method.** Story §7 explicitly out-of-scope; an ADR amendment
  is the bar if a future story needs it. Operational recovery is "delete
  the file."
- **Cache TTL / eviction.** Story §"Out of scope" — content-addressed
  growth is bounded by corpus size; Phase 11 reconsiders at portfolio
  scale.

### Lessons (cross-story candidates)

**L-S402-1 — A 1-byte zero file does NOT trip `sqlite3.DatabaseError`.**
The story §AC-7 says "simulate via a corrupt 1-byte file." Empirically,
`sqlite3.connect()` followed by `PRAGMA journal_mode=WAL` and a
`CREATE TABLE IF NOT EXISTS` all succeed on `b"\x00"` — sqlite
permissively treats a near-empty file as a fresh database. To exercise
the rebuild branch the fixture has to be sqlite-shaped (`b"SQLite format 3\x00"`
magic header) followed by garbage so the *body* read fails with
`DatabaseError: file is not a database`. The implementation handles
both cases correctly; only the test fixture needed the upgrade. Lesson
for future cache-corruption fixtures: assert the simulator *actually
raises the targeted exception* before relying on it.

**L-S402-2 — `structlog.testing.capture_logs` works at unit-test scope but
NOT for events emitted by code that re-binds `_log` after the
`with` block opens.** Caught by symmetry with the smoke conftest pattern
(`_disable_cli_configure_logging`). For unit tests of code that only
calls `_log` (no `structlog.configure`), `capture_logs()` is the right
tool — and `caplog` (pytest stdlib) won't see structlog events because
they don't route through stdlib `logging` here. Pin: use `capture_logs`,
not `caplog`, for structlog-only event capture.

**L-S402-3 — Float32 round-trip equality requires power-of-2 denominators.**
A test like `tuple(float(i) / 100.0 for i in range(384))` will *not*
survive `float64 → float32 → float64` because `0.01` has no exact float32
representation. Use `float(i) / 256.0` (power-of-2 denominator) for
exact roundtrip equality. The encoder is canonical in float32 — testing
against values that lose precision tests float arithmetic, not the
encoder contract.

**L-2 / L-4 recurrence (out of story scope).** Same documented

`tests/unit/test_lint_imports_canary.py` PATH issue. Both deselected
