### Refactor decisions

- **Reworded an existing CODEOWNERS comment** to remove the `>=` substring rather than weakening the AC-16 `<`/`>` placeholder-rejection test. Per Rule 7 (surface conflicts, don't average): the AC-16 spec is literal on the raw file text — relaxing it to "ignore comments" would erode the protection it was added for. The comment rewording is cosmetic; the placeholder protection stays strong.
- **Stripped backticks from the `cassettes.lock format` heading** rather than relaxing the heading-match test to strip them at compare time. The story spec's TDD plan asserts on substring match against a heading set — adding test-side stripping would mask a real wrong-heading mistake; the heading is plain text either way.

The test's own docstring said "Update this fence to whitelist `refresh-cassettes` in the S3-06 commit" — the contract author anticipated this exact change, and a parallel test would have introduced redundancy. Renamed to reflect the post-S3-06 invariant: `refresh-cassettes` is the **sole** setter.
- **No abstraction extracted from the Makefile gate.** The story explicitly notes "If a second token-spending target is ever added, generalise the `@if` block into a shared `_token-spend-gate:` prerequisite *then* (rule of three), not before." Followed Rule 2 (simplicity first) — one setter today, no premature shared-gate target.

### Lessons (cross-story candidates)

- **L-13: macOS pre-commit hook entries using bare `python` fail locally on default Python installs.** S3-05's `cassette-lock-check` hook (`entry: python -m codegenie cassette rebuild-lockfile --check`) exits 1 on macOS where only `python3` exists. CI Linux runners have `python` available so the hook passes there. A future story could either (a) widen the hook entry to `sys.executable`-equivalent resolution, (b) ship a `scripts/cassette-lock-check.sh` shim, or (c) document the local-env divergence in `docs/contributing.md`. Not blocking; same shape as L-2/L-4. Out of S3-06's scope per Rule 3 (surgical changes).
- **L-14: When the story spec writes a literal test assertion (`assert "<" not in text and ">" not in text`), prefer to fix the source data over loosening the test.** A test that strips comments to satisfy itself is no longer a guardrail. The CODEOWNERS comment rewording (`>=` → `at least one`) was the right move — Rule 9 (tests verify intent).
- **L-15: macOS default-PATH `subprocess.run` calls must use `sys.executable`, not bare `"python"`.** The MIN_ENV pattern (`{"PATH": "/usr/bin:/bin"}`) for gate-isolation testing strips inherited PATH including the venv. Tests invoking `python -m pytest` directly under MIN_ENV will hit FileNotFoundError on macOS because `/usr/bin` ships only `python3`. Use `sys.executable` for the interpreter when MIN_ENV is *not* in effect (the marker-collect test), and when MIN_ENV *is* in effect (the gate tests) call `make` which finds its own tools via the recipe.
