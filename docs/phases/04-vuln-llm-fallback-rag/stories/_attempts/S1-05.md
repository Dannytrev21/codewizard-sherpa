### Refactor decisions

- **Import-linter `forbidden_modules` follows the narrowing.** The two
  Phase-3 contracts (`codegenie.{plugins,transforms}`) and the Phase-7
  contract (`primitives.vuln_provenance`) all carried `["anthropic",
  "langgraph", "openai", "langchain", "transformers"]`. The Phase-3 +
  Phase-7 shape tests (`test_phase3_importlinter_contracts_shape.py`,
  `test_phase7_importlinter_contracts_shape.py`) couple `forbidden_modules`
  to `FORBIDDEN_LLM_SDKS` set-equality. Narrowing `_fence.py` alone would
  red the shape tests. **Decision:** update the three `forbidden_modules`
  lists *in this story* (drop `anthropic`, add `sentence_transformers` +
  `torch` — note `sentence_transformers` underscore form because
  import-linter scans Python *import* names while `_fence.py` uses *distribution*
  names) and change both shape tests to canonicalize both sides via
  `packaging.utils.canonicalize_name`. S1-06 (import-linter contracts) was
  the canonical home for these edits, but the coupling forces them here:
  Rule 12 (fail loud) — cannot ship with red shape tests. Logged the
  out-of-scope nudge below.
- **Two-phase fence CI job.** AC-22 asked for `tests/fence/` to run in the
  dedicated fence job, but the existing job is STANDALONE per Phase-0
  ADR-0006 (no `[dev]` install — closure-measurement hygiene). Tests under
  `tests/fence/` need `import-linter` (e.g.
  `test_lint_imports_catches_planted_leak.py`) which lives in `[dev]`.
  **Decision:** restructure into Phase A (closure measurement — bare,
  uncontaminated) → Phase B (after `[dev]` install — full path-scoped +
  audit-lint surface). The Phase-0 invariant survives because the
  closure-measurement test runs *before* any `[dev]` install. The CI
  workflow test gained an ordering-invariant assertion enforcing this.
- **Distribution vs import names handled at canonicalization, not at the
  set boundary.** `FORBIDDEN_LLM_SDKS` keeps the canonical PyPI form
  (`sentence-transformers`, hyphen). Per-package consumers that need import
  names translate locally (`sdk.replace("-", "_")` in `test_no_llm_in_transforms.py`
  / `test_phase7_no_llm.py` when synthesizing planted modules; `canonicalize_name`
  when intersecting against `sys.modules`). One canonical source of truth,
  one canonicalization function — no parallel sets.

### Planted-positive mutation guards updated

Two pre-existing tests parametrize over `FORBIDDEN_LLM_SDKS` and synthesize
`import {sdk}` in temp modules to verify the live scanner catches each one.
After narrowing the set to include `sentence-transformers` (hyphen),
`import sentence-transformers` becomes a `SyntaxError`. Both tests now
translate distribution → import name (`sdk.replace("-", "_")`) when
synthesizing the import statement and the temp filename, and the
`_scan_*_runtime_closure` helpers canonicalize both `sys.modules` keys
and `FORBIDDEN_LLM_SDKS` members before intersection so the post-walk
match is name-form-agnostic.

### Lessons for the next attempt

- A constant that's referenced as a set-equality source-of-truth (here:
  `FORBIDDEN_LLM_SDKS`) couples to every downstream consumer that pins
  shape against it. Narrowing the source-of-truth forces parallel edits to
  every shape test in the same atomic change — there is no "narrow now,
  fix the shape tests later" path that keeps CI green. Map all consumers
  before editing the constant.
- Distribution-name vs import-name is a real wedge for PyPI packages whose
  distribution name uses hyphens (e.g., `sentence-transformers`). When a
  test parametrizes over a distribution-name set and synthesizes `import
  {name}`, an SDK with a hyphen makes the synthesized code a syntax error.
  Either (a) translate at the call site (`name.replace("-", "_")`), or
  (b) keep two sets — one distribution, one import. Option (a) is more
  surgical and was chosen here.
- The CI fence job's STANDALONE invariant (no `[dev]` extras) is honest
  but limits what `tests/fence/` can assume. Restructuring into a
  closure-measurement phase + a post-install fence phase preserves the
  invariant without losing AC-22 coverage. The ordering invariant is
  asserted explicitly in the CI workflow test so a future PR cannot
  silently revert the discipline.
