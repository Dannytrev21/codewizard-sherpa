### Refactor decisions

- **Strategy pattern (deferred).** `EgressGuardPort` Protocol provides the Strategy/Ports-and-Adapters seam for S3-03's concrete `EgressGuard`. Did not register a registry — there is exactly one consumer (`AnthropicLeafAdapter`) so Open/Closed at the import-site beats premature dispatch.
- **Smart constructor (applied).** `_token_count_or_zero(value: int | None) -> TokenCount` and `_project_stop_reason(value: Any) -> _LeafStopReason` are both small pure helpers acting as smart constructors at the SDK→domain boundary. Keeping them at module scope (not class methods) preserves the functional-core / imperative-shell split.
- **Sum-type closure (applied).** `_LeafStopReason = Literal[...]` projected via `_project_stop_reason` instead of a `match` ladder inside `invoke`. The SDK's wider literal (which adds `pause_turn`/`refusal`/`None`) collapses to the four `LeafResponse` values without leaking SDK-shape into the leaf contract.
- **Capability pattern (preserved).** `BudgetToken` flows through `invoke(...)` as a typed signature requirement only — the adapter does not reconcile; reconciliation belongs to `FallbackTier` per ADR-0010 §Pattern fit.
- **Pure helpers vs imperative shell (preserved).** Pure: `_build_system_blocks`, `_build_output_config`, `_extract_first_text`, `_token_count_or_zero`, `_blake3_un_prefixed`, `_prompt_digest`, `_response_digest`, `_project_stop_reason`. Imperative: `invoke`, `_call_sdk_with_transport_retry`, `_load_key`, the four event emitters.
- **Markers-only exceptions (preserved).** `AnthropicKeyMissing` and `LeafProtocolViolation` are minimal exception classes with documented attributes (`first_error`/`second_error`); no markers-vs-events name collision (S3-02 §D3 — `LeafProtocolViolationEvent` is the matching event class).
- **`__slots__` (applied).** The adapter uses `__slots__` to deny `__dict__`, both as a memory micro-opt and as a structural guard against ad-hoc state mutation. AC-3 test had to be rewritten to iterate slots instead of `__dict__`.

### Followups surfaced this attempt (out of scope; not folded in)

- **Stop-reason widening.** The adapter projects unknown SDK `stop_reason` values (`pause_turn`/`refusal`) to `"end_turn"`. A future S3-0X (or a Phase-6 stop-reason audit) may want to emit an audit event when projection happens, so silent stop_reason drift isn't lost.
- **Cleartext-key SDK retention.** The adapter never retains the cleartext key on `self`, but the SDK client (`AsyncAnthropic`) does. The fence test exempts `_client` because that retention is intentional and out of S3-02 scope. If we later need stronger key-hygiene, the natural seam is wrapping the SDK transport rather than the adapter.
- **Pre-commit mypy hook dep drift.** Adding `anthropic` and `keyring` to the pre-commit `additional_dependencies` mirror list is a chore-rot risk: every future Phase-4 runtime dep needs a parallel entry. A `make precommit-deps-check` that re-derives the mirror from `[project.dependencies]` would close the loop. Not in scope here.
