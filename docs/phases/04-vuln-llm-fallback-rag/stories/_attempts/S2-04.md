### Refactor decisions

- **Newtype + Smart constructor (pattern reinforced).** `TrustedPrompt` /
  `FencedPromptBody` are `NewType("...", str)` co-located with the only
  function that mints them. The AST-walking sole-mint test makes the
  invariant load-bearing; without it, "smart constructor" is a polite
  convention, not a contract.
- **Functional core / imperative shell (reinforced).** Pure helper
  `_ordered_untrusted_segments` computes the `(SourceKind, payload)`
  ordering with no I/O and no event emission. The shell `build()` does
  the multiplicity-cap audit, fence-wraps each segment, mints both
  newtypes, and emits exactly one `PromptAssembled`.
- **Composition shell over `FenceWrapper` (deliberately not a Visitor).**
  ADR-0013 §Design patterns row 5 explicitly rejects the Visitor +
  Builder cascade — "readable explicit calls beat pattern soup". The
  `build()` body is a single list comprehension over the ordered pairs.
  AC-13's no-bypass test is the structural guard against drift toward a
  second fence implementation.
- **Discriminated-union additivity for events.** Adding
  `PromptAssembled` + `SegmentCountTruncated` is two new
  `WorkflowInternalEvent` variants + two appends to `_INTERNAL_CLASSES`
  + two appends to `__all__`. No edit to existing variants. The
  `test_all_21_internal_variants_exist` count-pinned guard fails loudly
  if a future story silently widens the set.
- **Multiplicity policy pinned, not implementer-choice.** The
  Validation note's third block called this out: 16-cap on
  `transitive_dep_meta` truncates with one `SegmentCountTruncated`; 3-cap
  on `rag_few_shots` raises `ValueError` before any fence call. The cap
  constants `_TRANSITIVE_DEP_META_CAP` / `_RAG_FEW_SHOTS_CAP` live as
  module-level `int`s — a future ADR amendment widens them by editing
  one row, not by adding branches.

### Anti-patterns avoided

- Primitive obsession on the prompt pair — `tuple[TrustedPrompt,
  FencedPromptBody]` instead of `tuple[str, str]`. Caller-site
  type-errors at the S3-01 `LeafLlm.invoke` signature catch
  hand-constructed `str` callers.
- Forking a second fence in `prompt_builder.py` — AC-13 AST-walk
  prevents this structurally.
- Spreading `BudgetToken` across the prompt assembly path — AC-9
  signature check is the structural guard against drift.

### Lessons

- The Validation-block "block" findings paid off twice. Pinning
  multiplicity behavior (the third block) removed all implementer
  ambiguity — the test rows fell out of the spec directly. Removing the
  stale `identifiers.py` fallback (the first block) avoided a future
  attempt log explaining why we backed it out.
- The forbidden-literal substring check in AC-13 caught itself: my
  initial module docstring referenced `<UNTRUSTED_INPUT id=...>` to
  explain what the builder must not assemble. Removed; the docstring
  now refers to "the per-nonce open/close delimiters that `fence_pure`
  owns". Self-applying structural checks is a good smell test.
- The 2-failure pre-existing `lint-imports` PATH issue (S2-01/02/03 saw
  the same) needs an env fix at some point — but is unrelated to story
  scope and re-runs green with `PATH="$VENV/bin:$PATH"`.
