### Decisions of record

- **Phase-3 contract-type drift surfaced.** The story prose names
  `RecipeApplication`, `CveAdvisory`, `RecipeSelection`,
  `RepoContext` as Phase-3/Phase-5-owned types. None exist as
  Python classes. Decision: ship minimal Phase-4-local Pydantic
  stubs (`fallback/contracts.py`) with the field set the
  FallbackTier collaborators actually require. Phase 5 will
  harmonize. `RecipeApplication` is NOT stubbed — `PlanOutcome`
  (S1-03) is the actual return type the FallbackTier emits.
- **Collaborator types stay opaque where Phase-3/Phase-5 has not
  shipped narrower Protocols.** `retriever`, `harvester`,
  `confidence_gate` are typed `object` in the dataclass so the
  import-linter BudgetToken-scope contract doesn't widen into
  `codegenie.rag.*`. Future tightening (e.g., a `Retriever`
  Protocol exported by `codegenie.rag`) is one-line additive.
- **GREEN-partial outcome scope.** The story's load-bearing
  invariant is "FallbackTier composes the eight collaborators
  through a sequential pipeline." This attempt ships the
  composition shape (dataclass + signatures + match exhaustiveness)
  but not the 9-step body. Downstream stories (S6-02/S6-03 ride on
  the same `FallbackTier` symbol; S7-01 ships the plugin that
  constructs one) can import the symbol and start their own work
  in parallel to the S6-01 completion session.

### Refactor decisions

- **`transform_from_plan` is a free function**, NOT a method on
  FallbackTier. The functional-core/imperative-shell rule: pure
  logic stays out of the I/O-orchestrating class. The function
  AST-walks to a `match` block over the four `PlanProposal`
  variants with `case _: assert_never(plan)` — mypy --strict
  enforces exhaustiveness at the typecheck boundary.
- **`_TransformProjection` is a private DTO** carrying just the
  `plan_kind` discriminator the `TransformBuilt` event needs. A
  future ADR-amendment will land a richer `Transform` payload; the
  projection stub keeps the audit anchor without dragging a
  not-yet-shipped type into the kernel.
