### Refactor decisions (design-patterns walk)

- **Smart constructor + Newtype** — used as designed: `TokenCount` is a `NewType` (carries no runtime validation); `Field(ge=0)` is the runtime guard. `LeafResponseId`/`ModelId` are existing `NewType`s from S1-01.
- **Tagged union** — `plan: PlanProposal` consumes the existing closed discriminated union from S1-02; no widening here.
- **Ports & adapters / Strategy** — the Protocol *is* the port; concrete adapters (`AnthropicLeafAdapter` S3-02; second vendor per production ADR-0020) are the strategies. Kept the Protocol SDK-free so the second vendor isn't blocked.
- **Capability pattern** — `token: BudgetToken` is the capability; keyword-only + required + `import-linter` two-frame scope.
- **Composition over inheritance** — `LeafResponse` is a `BaseModel`, no inheritance chain; the Protocol is the only abstraction.
- **Make illegal states unrepresentable** — `stop_reason: Literal[...]` (closed 4-set); `frozen=True` + `extra="forbid"`; `Annotated[..., Field(ge=0)]` makes negative counts unrepresentable.
- *Deferred* — no Strategy registry yet (only one consumer of `LeafLlm` until S3-02 lands).

### Lessons (also folded into `_lessons.md`)

- **L-7 — A `# type: ignore[<code>]` on the call site under test is the worst possible diagnostic suppression.** S2-05 wrote `tests/fixtures/typecheck/budget_token_missing.py` with `# type: ignore[call-arg]` on the very call whose missing-argument the gate asserts on. While the import was unresolved (`importorskip` skipped the test), nobody noticed. When S3-01 turned the gate live, mypy succeeded — exactly the failure mode the gate exists to catch. Lesson: a fixture asserting "mypy errors with diagnostic X" must NEVER suppress X inline. Suppress the *expected noise* (placeholder values, unrelated arg-types) but leave the diagnostic-under-test surfaced.
- **L-8 — Cross-story name drafts must be reconciled before the gate flips.** S2-05 named the module `codegenie.fallback.leaf.protocol`; S3-01 (the contract owner — AC-1 names `port.py`) was the load-bearing source. The validator surface-area review of S3-01 had already flagged AC-10 as "subsumed by AC-4" because it pointed at a not-yet-existent S3-02 test — the *same class* of cross-story-stale-path bug. The S3-01 executor's reconciliation closes this loop; future "gated on next story" tests should pin the module path to the next story's canonical surface, not a draft name.
