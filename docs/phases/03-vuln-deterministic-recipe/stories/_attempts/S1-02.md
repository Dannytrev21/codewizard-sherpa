### Refactor decisions (design-patterns lens)

- **Sum type over magic strings.** `Concrete | Wildcard` makes `Wildcard()` vs. `Concrete(value="*")` a static-type discriminant — the resolver's `if dim == "*"` anti-pattern (ADR-0033) can't be re-introduced. Validated against the closest in-repo precedent — `IndexFreshness = Fresh | Stale` at `src/codegenie/indices/freshness.py` (Phase-2 S1-01). That precedent uses Pydantic discriminated unions; we deliberately chose dataclasses here per ADR-0010 §Decision §1 (smaller, faster, native `match` over the variant set without Pydantic re-validation).
- **Functional core / imperative shell.** `parse` is the only public class method that constructs `PluginScope` from untrusted input; the kernel methods (`matches`, `specificity`, `__str__`) are pure. The helpers `_dim_admits`, `_is_concrete`, `_dim_to_str` are module-private pure functions, each carrying its own `assert_never` arm so AST-checked exhaustiveness travels with the dispatch site. Mirrors the Phase-2 `freshness.py` and `result.py` precedents.
- **Smart constructor.** `PluginScope.parse(s)` is the only safe entry; defense-in-depth `__post_init__` validation on `Concrete` was rejected (ADR-0010 §Decision §1 — bare dataclass; smart constructor is the boundary). This matches the Phase-3 S1-01 `parse_<x>(s) -> Result[T, ParseError]` family in `codegenie/types/parsers.py`.
- **Make illegal states unrepresentable.** The dim regex + length cap reject every adversarial input in the R1–R17 matrix; the type system rejects `Wildcard("*")` (zero-field dataclass) and `Concrete()` (missing required field). Adding a third variant requires updating every `match` block — AST test + `assert_never` arms make this a build-break.
- **`Final` tuple/constant catalog for the regex + separator.** The module-level constants are iteration-friendly (S2-02 manifest loader can re-use `_DIM_PATTERN` and `_DIM_MAX_LEN` directly) and avoid magic numbers / strings sprinkled through the dispatch helpers. Mirrors `_GENERATOR_HEADER_MARKERS` / `_REFLECTION_QUERIES` / `_LOCKFILE_PRECEDENCE` in Phase-2 probes.

### Rule-7 surfaces

1. **Hypothesis strategy regex tightened vs. literal AC-15 wording.** Story AC-15 prescribes a strategy aligned to the parse regex `^[a-z0-9_-]{1,64}$`. That admits leading / trailing hyphen — e.g. `Concrete(value="0-")` — which produces an *ambiguous* `__str__` form when joined by the `--` separator: e.g. `"*--0---0".split("--") == ["*", "0", "-0"]`, not the original triple. The Hypothesis round-trip property (AC-11 / AC-20) cannot hold over that subset. Two options surfaced:
   - **Tighten the parse regex** to forbid leading / trailing hyphen. Rejected — directly contradicts AC-5's "exact dim regex `^[a-z0-9_-]+$`".
   - **Tighten the Hypothesis strategy** to the round-trippable subset: `^[a-z0-9_]([a-z0-9_-]{0,62}[a-z0-9_])?$` (1–64 chars, no leading / trailing hyphen). This honours AC-5 (parse regex unchanged) and matches the intent of "any constructible scope" in AC-11 — *constructible-via-parse* scopes, not arbitrary dataclass-constructible ones. The rejection matrix R1–R17 still exercises the literal regex via `parse()` directly.

   Chose **Option 2**. Documented in `test_scope.py` `scope_dims()` strategy with a docstring comment that names the ambiguity. Hardening note: the validator's S1-02 audit (per `_validation/S1-02-plugin-scope-sum-type.md`) widened the strategy from the original `[a-z][a-z0-9_-]{0,16}` to the full parse regex; this attempt-log entry narrows it again to the round-trippable subset. The two changes are not in contradiction — the validator was correctly closing the "leading digit / underscore" gap, and this fix correctly closes the "leading / trailing hyphen" gap discovered at GREEN time.

2. **Arch §C3 newtype-typed `matches` signature.** `phase-arch-design.md §C3` shows newtype-typed parameters on `PluginScope.matches`. Story Notes-for-implementer §"PluginScope.matches signature uses str, not newtypes" overrides: the kernel stays task-class-agnostic so a Phase-7 distroless plugin and a Phase-3 vuln-remediation plugin can share the same `PluginScope` type. Implementation followed the story's `str` signature; documented at `scope.py:118-122` so a future reader doesn't "fix" the signature.

### Lessons

1. **AC-15 strategy alignment with AC-11 round-trip needs a non-ambiguous-encoding clause.** When a separator can also appear inside a dim, the round-trippable subset is strictly smaller than the parse-admissible subset. Future similar stories (e.g., manifest-key parser, branch-name parser, lockfile-key parser) should add a "no leading / trailing separator-char" clause to the Hypothesis strategy or pre-filter via `assume()`.
2. **`assert_never` arms migrate to private helpers when the public method is a one-line dispatch.** Initial design put a `match` directly in `matches` / `specificity` / `__str__`. Final shape factors each dispatch into a pure helper carrying its own `assert_never`; the public method becomes a single-line `match` whose `case _:` arm also calls `assert_never`. The AST test (AC-14) walks ALL `Match` nodes — both the public-method dispatches and the helper dispatches contain the wildcard arm. This is the cleanest factoring observed across the Phase-2 / Phase-3 precedents.
3. **`make check` requires `.venv/bin` on `PATH`.** The Makefile invokes bare `ruff`, `mypy`, `mkdocs` rather than `.venv/bin/...` — set `PATH="$(pwd)/.venv/bin:$PATH"` before invoking. Same lesson recorded in S1-01.
