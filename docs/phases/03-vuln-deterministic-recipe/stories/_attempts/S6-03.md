### As-built drift resolutions

The story was HARDENED on 2026-05-19, *before* S6-02 landed (2026-05-21).
Seven as-built reconciliations were applied; the Goal and all 23 ACs are
honoured.

- **D-1 — field-type imports are runtime, not `TYPE_CHECKING` (outline §3
  drift).** Outline §3 prescribed importing `PluginResolution` / `Bundle` /
  `RecipeOutcome` / `Transform` / `TrustOutcome` under `if TYPE_CHECKING:`.
  That is unworkable: all five are Pydantic *field annotations* on
  `SubgraphState`, and Pydantic must resolve a field's type at runtime to
  build the model. With those imports type-checking-only, `SubgraphState(...)`
  — constructed by ~6 ACs' tests — raises `PydanticUndefinedAnnotation`. All
  five are imported at runtime. Safe: every dependency story is GREEN so the
  modules exist, and `subgraph.py` is brand-new so nothing imports it back
  (no cycle — verified by the per-submodule cold-start fence). AC-12's
  build-order rationale is moot — S6-02 already landed. The AC contract
  (`SubgraphState` constructible with the 8 typed fields) is honoured.
- **D-2 — `SubgraphState.model_config` carries `arbitrary_types_allowed=True`.**
  AC-9 spelled the config `ConfigDict(frozen=True, extra="forbid")`. The
  `transform: Transform | None` field needs `arbitrary_types_allowed=True`
  because `Transform` is an `abc.ABC` (`transform.py:64`), not a Pydantic
  model — without the flag Pydantic raises `PydanticSchemaGenerationError`
  at model-build time. Mirrors the shipped `ConcreteResolution` precedent
  (`resolver.py:158` — an `Adapter`-Protocol field under the identical
  config). AC-9's intent (frozen + extra-forbid + the 8 fields) is preserved.
- **D-3 — `TrustOutcome` imported from `transforms.outcomes`, not
  `transforms.trust_scorer`.** Outline §3 / AC-12 named `trust_scorer` as
  the `TrustOutcome` home. As-built (S6-02), `TrustOutcome` lives canonically
  in `transforms/outcomes.py`; `trust_scorer.py` only re-exports it. Importing
  from the canonical site is the single-source-of-truth choice; class
  identity is identical either way.
- **D-4 — `test_exhaustiveness.py` migrated (not in the story's
  Files-to-touch).** `test_exhaustiveness.py:108` also constructed
  `Advance(state={})`; the story's outline §6 only named `test_outcomes.py`.
  Migrated the one site to a `SubgraphState`.
- **D-5 — `test_outcomes.py` `test_json_shape_keysets_pinned` migrated.**
  Outline §6 said "any other test referencing `Advance` with a dict literal
  — none expected per grep"; there was one. Migrated.
- **D-6 — `test_outcomes_purity.py` import allowlist widened.** `outcomes.py`
  needs `if TYPE_CHECKING: from codegenie.plugins.subgraph import
  SubgraphState` for `mypy --strict` to resolve the `Advance.state`
  annotation. `test_imports_are_kernel_only` AST-scans *all* imports
  (TYPE_CHECKING blocks included), so `codegenie.plugins.subgraph` was added
  to `_ALLOWED_IMPORT_ROOTS` with a comment. Runtime kernel-purity of
  `outcomes.py` is unchanged (the guarded import never executes).
- **D-7 — AC-15's two replacement tests live in `test_subgraph_protocol.py`,
