### Refactor decisions (design-patterns lens)

- **Newtype identifiers (already in place).** `PluginId`, `RegistryUrl` carry the capability fields. No primitive obsession.
- **Smart constructor (`mint`).** Capabilities are only constructed inside `mint()`. The chokepoint is enforced at file level (AST line-range check) AND repo-wide (`_capability_fence`). Two-tier defence — accidental bypass requires deliberate intent.
- **Sum type (`CapabilityScope`).** Closed union over `NpmScope | FsScope | GitLocalOpsScope` (TypeAlias, NOT base class). `mint()` dispatches via `isinstance` with `assert_never` in the final else — mypy --strict pins exhaustiveness.
- **Sum type (`CapabilityBundle`).** `model_validator` enforces "exactly one non-None" — illegal states (zero or two capabilities) raise `ValidationError`.
- **Type-level invariant (`GitLocalOpsCapability` has no `push` field).** Three assertion layers: (a) `"push" not in model_fields`, (b) constructor with `push=True` raises `ValidationError(match="push")`, (c) docstring carries the canonical "no push field" phrase + ADR cross-references.
- **Functional core / imperative shell.** `find_violations` is a pure function over file paths; `_violations_for_source` is pure over `(src, path)`. The single I/O is `path.read_text` at the boundary.
- **Open/Closed via data, not branches.** `_CAPABILITY_CLASS_NAMES` is a `Final[frozenset[str]]`; adding a fourth capability is a one-line append. `ALLOWED_BINARIES` follows the same discipline (ADR-amend, not kernel-edit).
- **Extension-by-addition for `mint()` dispatch — deferred.** The story validator note flagged a future refactor to a registry-based Strategy when the fourth scope type lands (Phase 7 `ContainerOpsScope` likely). Three concrete variants today do not pay for the abstraction (Rule 2).

### Trade-offs deliberately taken

1. **`monkeypatch.setattr` direct-form (NOT string-form) for `_emit_capability_minted`.** During development a cross-test interaction surfaced: `tests/fence/test_no_llm_in_transforms.py::test_scanner_catches_each_planted_sdk_under_phase3` pops/restores `codegenie.plugins.*` in `sys.modules` to test the LLM-SDK scanner. After restore, the parent `codegenie.plugins` package's `capabilities` attribute holds the post-walk (NEW) module, NOT the snapshot's OLD module. `monkeypatch.setattr("codegenie.plugins.capabilities._emit_capability_minted", spy)` walks via `getattr` on the parent and patches the stale NEW module, while `mint()`'s `__globals__` points at the OLD module that was originally loaded into `test_capabilities`'s namespace. The direct-form `monkeypatch.setattr(capabilities_mod, "_emit_capability_minted", spy)` binds the patch to the actual module object `mint` resolves against. The story said "this story emits via a forward-declared sink"; the chokepoint discipline is preserved, the call shape (AC-14) is unchanged, only the test's monkeypatch shape moved.

2. **`populate_by_name=True` on capability models.** The story's AC-12 prescribes `_minted_by=<value>` as a kwarg. Pydantic v2 supports underscore-prefixed field names via `alias="_minted_by"` (the Python attribute is `minted_by` for sane access). Without `populate_by_name=True`, JSON round-trip fails: `model_dump_json` emits `"minted_by"` but `model_validate_json` would only accept `"_minted_by"`. Adding `populate_by_name=True` admits both forms on input, preserving the AC-12 kwarg shape AND the round-trip identity (AC-Sub-3).

3. **Negative-list closed-set: `bwrap` removed, `bubblewrap` STAYS.** The story explicitly required this asymmetry (validator resolution 2). The symmetric ratchet is recorded in two locations: the parametrize list (`tests/unit/test_exec.py`) and a dedicated `test_bubblewrap_long_name_remains_disallowed` assertion.

4. **`_NPM_LIFECYCLE_SUBCOMMANDS` catalog extension.** The original story's `{install, test, ci, audit, ls}` was insufficient — `rebuild` is the single subcommand that exists to run lifecycle scripts. The hardened catalog covers `install`, `i`, `ci`, `test`, `t`, `rebuild`, `rb`, `update`, `up`, `pack`, `publish`, `exec`, `run`, `run-script`, `start`, `stop`, `restart`. Advisory commands (`audit`, `ls`) deliberately excluded — they do NOT run lifecycle scripts, and the fence flagging them would be a false positive when an npm engine legitimately invokes `npm audit --json` for SBOM purposes.

5. **Fence walker home in `src/codegenie/` (NOT `tooling/`).** ADR-0011's original wording named `tooling/ruff_rules/no_capability_construction.py`. The codebase has no `tooling/` directory and `src/codegenie/_phase3_fence.py` is the established precedent (Rule 11). The walker home is `src/codegenie/_capability_fence.py`, consumed from `tests/fence/test_capability_fence.py`. ADR-0011 §Consequences amended in this story (one-line edit).
