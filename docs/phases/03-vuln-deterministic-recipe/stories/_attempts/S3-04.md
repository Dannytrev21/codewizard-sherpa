### Design-pattern observations

- **`AdapterDispatch` as typed Callable, not Protocol** — matches the story's prescription. Per-primitive function adaptation lands cleanly in S7-02 (`scip_adapter.refs → scip.refs`).
- **`BundleResolution` Protocol** — structural typing at the consumer boundary. Concrete `ConcreteResolution` (in `codegenie.plugins.resolver`) does NOT today have `composed_dispatch`; S7-02 will widen it (or wrap it). The Protocol keeps tests honest without requiring production wiring to land first.
- **Functional core / imperative shell** — `_compose_entry` is `def` + no I/O + no Awaits (AST-pinned). `_resolve_chain` is `async def` + iterative + semaphore-free. `_acquire_then_dispatch` holds the semaphore for the whole top-level chain so the cap-arithmetic is straightforward.
- **`BundleBuilderError` as Pydantic model, exception via thin `BundleBuilderRaise` wrapper** — mirrors S3-01's `TCCMParseError` pattern. Markers-only `CodegenieError` discipline stays clean; typed `.error.reason` lookup at the catch site stays ergonomic.
- **Cap arithmetic** — story body §3 and AC-17 boundary tests had subtle disagreement on the increment-vs-check ordering. The implemented logic checks `depth >= _MAX_FALLBACK_DEPTH` at the **start of each iteration** (before dispatching) and reports `details["depth"] = depth + 1` — the "depth we tried to reach". This satisfies both the 4-deep success (3 emits + Trusted leaf) and 5-deep raise (4 emits + 1 FCTD with depth=5) test prescriptions in a single rule. See the inline comment in `_resolve_chain` for the operator-readable rationale.

### Cross-test stability note

Two tests (`test_degraded_with_no_fallback_returns_best_effort` and `test_missing_primitive_in_dispatch_table_raises`) initially had inline imports of `TCCM` + `FakeResolution`. Under the full suite, `tests/fence/test_no_llm_in_transforms.py` pops and re-imports `codegenie.plugins.*` from `sys.modules` for its planted-import test; the inline-import tests then saw a class-identity mismatch between the OLD `_make_query` output (cached in `_bundle_fixtures.py`) and the NEW `TCCM` class. The fix was to move both imports to the test file's top-level (so all class references are pinned at the same collection moment as `_bundle_fixtures.py`). After the move, all 4,772 tests pass in the full suite.
