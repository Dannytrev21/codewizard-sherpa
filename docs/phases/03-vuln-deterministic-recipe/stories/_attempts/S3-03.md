### Refactor decisions

- **`_safe_json_load` returns `Result[object, VulnParseError]` from the canonical `codegenie.result` module** rather than a story-local sum-type. Initially scaffolded a tiny private `_LoadResult` class to avoid Pydantic's `T=object` overhead — collapsed to `Result` to match the established convention (`parsers.py` uses `Result`, S1-04 sets the precedent). The Pydantic `arbitrary_types_allowed=True` config on `Ok`/`Err` accepts `object` cleanly.
- **`parse_semver` lives in `codegenie.types.parsers`, not `identifiers.py`** — the AC-S6 wording "`identifiers.py` extended ... with `SemverVersion = NewType` plus `parse_semver`" reads informally; the matching codebase convention (S1-01 + S3-02 `parse_package_name` precedent) puts the NewType in `identifiers.py` and the smart constructor in `parsers.py`. The story's intent (additive extension at the kernel-tier boundary) is preserved; the deviation is bounded by Rule 11.
- **`AffectedRange` field-validators use `mode="before"` + `parse_semver`** rather than a separate parser-side coercion. Pydantic does the runtime coercion (`str -> SemverVersion`); mypy honest-typing is preserved at the field declaration. Callers that historically passed raw `str` (S3-02 tests; `index._row_to_record`) now use `AffectedRange.model_validate({...})` so mypy --strict stays green.
- **Per-source digest computation reuses the BLAKE3 chokepoint via `identity_hash`** (Phase 0 ADR-0001) — feed records are sorted by `cve_id ASC` then concatenated through `\x1f`/`\x1e` ASCII separators (reserved control chars, eliminate ambiguity with JSON content). Strip the `"sha256:"` prefix at the storage boundary to match `BlobDigest`'s 64-hex shape (mirrors `VulnIndex.digest`'s pattern).
- **Click adapter for `vuln-index refresh`** wraps the typed-exception body in a small `try/except CodegenieError` that maps via `_EXIT_CODE_DISPATCH`. The `gather` command has its own larger try/except (verbose / cli.start / cli.end logging); the refresh path is simpler and uses a focused adapter.

### Lessons (cross-story candidates)

- **Pydantic `mode="before"` field validators + `model_validate` at construction sites** are the cleanest combination when migrating a typed field from a raw `str` to a NewType. The runtime validator coerces; the typed annotation stays honest; callers use `model_validate({...})` to satisfy mypy --strict without proliferating `cast()` calls. Mirrors the S3-02 `coalesce-empty-string-to-None` pattern.
- **Registry-pattern at rule-of-three threshold.** This is the THIRD `@register_*` decorator-registry in `codegenie` (after `@register_index_freshness_check` and `@register_dep_graph_strategy`). The kernel-extract opportunity (shared `KernelRegistry[K, V]` base) crosses the threshold; intentionally NOT pre-extracted (Rule 2 — Simplicity First). When Phase 4 lands a fourth (recipe-engine registry — S5-01), revisit.
- **Snapshot tests need to be widened, not frozen.** S3-03 had to amend FOUR snapshot tests (`_EXIT_CODE_DISPATCH`, `errors.__all__`, `identifiers.__all__`, `_KERNEL_ALLOWLIST`) to land additively. Each amendment carries a one-line comment naming the new entry's owning story. Pattern: pin the SHAPE (every member documented somewhere) rather than the SET (exactly these N members) — the SET form fails noisily on every additive extension; the SHAPE form fails only on real drift.
- **`DOCUMENTED_MODULE_SLUGS` in `tests/unit/test_errors.py`** is the catalog of which sub-modules can raise a `CodegenieError` subclass. Adding a Phase-3 raise site at a new sub-module (e.g., `vuln-index`) requires appending its slug — the test's `f"{name} docstring must name one of the documented module slugs"` assertion guides the discovery.
