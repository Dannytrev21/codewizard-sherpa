### Blocker A (root cause — shared verbatim with S5-02)

S5-03 specifies **two** things that cannot both be true:

1. **2-tuple `apply` return contract** — Goal text + AC-Contract-1 (line
   119): `OpenRewriteRecipeEngine.apply(...) -> tuple[RecipeOutcome,
   Transform | None]`. Every TDD-plan test destructures it: `outcome,
   transform = await engine.apply(...)`.
2. **AC-Surface-2(b)** (line 94): *"a mypy-strict assignment `_engine:
   RecipeEngine = OpenRewriteRecipeEngine(jail=fake_jail)` type-checks
   (fence file runs `mypy --strict` ... asserts exit code 0)."*

The **landed** `RecipeEngine` Protocol — shipped GREEN by S5-01 on
2026-05-19 at `src/codegenie/transforms/recipe_engine.py:82-91` — is:

```python
@runtime_checkable
class RecipeEngine(Protocol):
    async def apply(
        self, repo: SandboxedPath, plan: ApplicationPlan,
        capability: NpmInstallCapability,
    ) -> RecipeOutcome: ...
```

`apply` returns **`RecipeOutcome`** — a single value, **not** a tuple.
`tuple[RecipeOutcome, Transform | None]` is not assignable to
`RecipeOutcome`, so `_engine: RecipeEngine = OpenRewriteRecipeEngine(...)`
fails `mypy --strict` with `Incompatible types in assignment`. **AC-Contract-1
and AC-Surface-2(b) are mutually unsatisfiable.** `RecipeEngine` is
`@runtime_checkable`, so AC-Surface-2(a) (`isinstance`) would pass
regardless — Python's runtime Protocol check ignores method signatures.
Only the **mypy half** breaks. This is the same defect documented in
`_attempts/S5-02.md` Blocker A and cross-story lesson `_lessons.md` #16.
