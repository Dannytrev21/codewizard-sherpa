### Blocker A (root cause) — `apply` return contract contradicts AC-Surface-2

S5-02 specifies **two** things that cannot both be true:

1. **The `apply` return contract** (story §"Acceptance criteria" convention
   block, lines 92–93; AC-Apply-1, line 147):
   ```python
   async def apply(self, repo, plan, capability)
       -> tuple[RecipeOutcome, NpmLockfileTransform | None]
   ```
   AC-Apply-1: *"Happy path returns `(Applied(...), NpmLockfileTransform(...))`
   (a 2-tuple)."* Every TDD-plan test destructures it: `outcome, transform =
   await engine.apply(...)`.

2. **AC-Surface-2(b)** (line 98): *"a mypy-strict assignment
   `_engine: RecipeEngine = NpmLockfileRecipeEngine(jail)` type-checks."*

The **landed** `RecipeEngine` Protocol — shipped GREEN by S5-01 on
2026-05-19 at `src/codegenie/transforms/recipe_engine.py:82-91` — is:

```python
@runtime_checkable
class RecipeEngine(Protocol):
    async def apply(
        self, repo: SandboxedPath, plan: ApplicationPlan,
        capability: NpmInstallCapability,
    ) -> RecipeOutcome: ...
```

`apply` returns **`RecipeOutcome`** — a single value, **not** a tuple.

For `_engine: RecipeEngine = NpmLockfileRecipeEngine(jail)` to type-check
under `mypy --strict`, `NpmLockfileRecipeEngine.apply`'s return type must be
covariantly assignable to the Protocol's. `tuple[RecipeOutcome,
NpmLockfileTransform | None]` is **not** assignable to `RecipeOutcome`. mypy
emits `Incompatible types in assignment` on the `apply` member. **AC-Apply-1
and AC-Surface-2(b) are therefore mutually unsatisfiable.**

Note `RecipeEngine` is `@runtime_checkable`, so AC-Surface-2(a) (`isinstance`)
would pass regardless — Python's runtime Protocol check ignores method
signatures. Only the **mypy half** breaks. The validator's harden-grade
correction #18 deliberately *strengthened* AC-Surface-2 to require the mypy
assignment; harden-grade correction #2 *independently* rewrote `apply` to
return the 2-tuple. The two corrections contradict each other — the
validator changed `recipe_engine.py`-conformance and the return shape in the
same pass without cross-checking S5-01's landed Protocol.

### Why the executor cannot resolve it

The three architecturally-sound fixes all sit **outside S5-02's authority**:

- **(a) Change the `RecipeEngine` Protocol return type to the 2-tuple.**
  Requires editing `recipe_engine.py` — *not* in S5-02's "Files to touch"
  — and S5-01 is `Done — GREEN`. The Protocol is frozen by **phase-3
  ADR-0001** (Phase-5 contract snapshot); changing it is an ADR amendment +
  an S6-06 contract-snapshot re-baseline, i.e. architect scope.
- **(b) Give the `Applied` variant a channel to the `Transform` instance.**
  `outcomes.py::Applied` carries only `transform_id: TransformId` (a
  BLAKE3-hex string). Adding a field to reach the Transform object is an
  `outcomes.py` change frozen by ADR-0001 — architect scope.
- **(c) Introduce a `TransformRegistry`** so `apply` returns plain
  `RecipeOutcome` and the orchestrator looks the Transform up by
  `Applied.transform_id`. `grep -rn "TransformRegistry|register_transform"
  src/codegenie/` returns nothing — no such registry exists. The `Applied`
  docstring *names* "the S1-04 `Transform` registry" but S1-04 shipped only
  the `Transform` ABC (`transform.py`), no registry. Building one is a new
  story, not a Files-to-touch line in S5-02.

The README manifest (line 158) describes a **third, also-wrong** shape —
`RecipeOutcome.Applied(NpmLockfileTransform(...))` (Applied carrying the
Transform *instance*) — which validation note #2 explicitly identified as
drift. Three documents, three incompatible shapes for how the Transform
leaves `apply`. This is a design-coherence defect, not an implementation
detail an executor can paper over.

### Secondary contract drift (fix these in the same rewrite)

These are *fixable by addition* and are **not** the blocker, but a rewrite
should clear them so the next executor pass runs clean:

- **`RegistryAllowlist.hosts` shape.** AC-4c asserts
  `spec.network.hosts == ("registry.npmjs.org",)` and the implementation
  outline (Step 4 §199) declares
  `_REGISTRY_ALLOWLIST_HOSTS: Final[tuple[str, ...]] = ("registry.npmjs.org",)`.
  The **landed** `sandbox_jail.py:148` field is
  `hosts: frozenset[RegistryUrl]`, and its validator (`:150-172`) rejects
  any host not prefixed `https://`. The engine must construct
  `RegistryAllowlist(hosts=frozenset({RegistryUrl("https://registry.npmjs.org")}))`
  and AC-4c must assert against that `frozenset`, not a bare tuple.
- **`JailedSubprocessResult` has 6 variants, not 5.** AC-Tax-1 pins
  `_NpmLockfileErrorId` at **exactly 13** entries and AC-4g enumerates only
  `Completed | TimedOut | OomKilled | NetworkDenied | DiskQuotaExceeded`.
  The landed union (`sandbox_jail.py:277-280`) also includes
  **`JailSetupFailed`**. AC-4g's `assert_never` exhaustive `match` cannot
  compile under `mypy --strict` without a sixth arm, and that arm has no
  `error_id` in the 13-entry taxonomy. The rewrite should add a 14th id
  (`recipe.jail_setup_failed`) and bump AC-Tax-1's count to 14.

### As-built contract drift resolved (the story is HARDENED but the validator
missed several as-built shapes; the Re-execution note anticipated this)

1. **Taxonomy 13 → 14.** `JailedSubprocessResult` ships a sixth variant
   `JailSetupFailed` (S4-01 GREEN). `assert_never` exhaustiveness (AC-4g2)
   needs a sixth `match` arm with an `error_id`; added `recipe.jail_setup_failed`.
   This was Attempt-1's own explicit recommendation.
2. **`NpmInstallCapability` has no `event_id`.** The story's `capability`
   fixture (`NpmInstallCapability(event_id=…)`) is drift — the S4-05 model
   carries only `registry` + `minted_by`. `TransformProvenance.capability_use_id`
   is derived deterministically by digesting the capability
   (`_derive_capability_use_id`): the capability is genuinely threaded, the
   anchor is stable per-capability, and S6-04 may wire a real minted event id
   additively when the orchestrator lands.
3. **`Applied` / `TransformProvenance` need `plugin_id` + `recipe_id`** with no
   plan/capability source named by the story. Resolved: `plugin_id =
   capability.minted_by` (honest), `recipe_id = RecipeId(str(transform_kind))`
   (1:1 in Phase 3), `plugin_version`/`recipe_version` = `"3.0.0"` `Final`
   constants documented as S6-04-injectable.
4. **`RegistryAllowlist.hosts` is `frozenset[RegistryUrl]`** of `https://`
   URLs, not a bare-hostname tuple — `_REGISTRY_ALLOWLIST_HOSTS` corrected to
   `frozenset({RegistryUrl("https://registry.npmjs.org")})`.
5. **`RecipeError.details` forbids list values** (`dict[str, str|int|bool
   |float]`). `sections_searched` is a comma-joined string; lockfile
   `supported` is the int `3` (the story's `["dependencies", …]` /　`[3]` list
   shapes are uninstantiable).
6. **`SandboxedPath` is the real S4-04 class** (`_forward` re-exports it) —
   `SandboxedPath(absolute=…)` / `.create()`, not `SandboxedPath(path)`. So
   AC-3b's `skipif(SandboxedPath is pathlib.Path)` is False — the symlink
   TOCTOU test **runs** (not skipped) and passes.
7. **No `Any` in the Phase-3 surface** — `tests/fence/test_no_any_in_plugin_surface.py`
   forbids it. JSON docs are typed `dict[str, object]` (`_JsonObject`), not
   `dict[str, Any]`; consumers narrow with `isinstance`.
8. **`_InternalError` is one private model, not four** (outline §5 prescribed
   four structurally-identical classes). Rule 2 + Rule 7: a discriminated
   union of four identical models is pure ceremony. One frozen Pydantic model
   honors validation-note-#7's spirit (concrete model, no `Result` kernel).
9. **Helpers return `T | _InternalError`, not the `(T|None, err|None)`
   2-tuple** — the tuple forces a bare `assert` (banned by `forbidden-patterns`)
   or a dead None-branch; a plain union narrows cleanly by `isinstance`.
10. **`orjson` was on a Phase-2 forbidden-dep list.**
    `tests/unit/probes/test_test_inventory.py::test_no_lcov_parse_pypi_dep_added`
    (Phase-2 AC-51) banned `orjson` repo-wide. That ban was over-broad — its
    real intent is "no LCOV-parser dep". Per Rule 7 the more recent
    ADR-backed decision (S5-02 / arch §C12) wins; `orjson` removed from that
    list with an inline rationale. The four LCOV-specific tokens still pinned.
11. **`from_version`/`to_version` carry no semver regex** — npm range
    specifiers (`^4.17.1`) are not bare semver; AC-Plan-1's "`_SEMVER_RX`"
    wording contradicts the story's own fixture data.
12. **AC-2d `TransformProvenance.details["edited_section"]`** — the as-built
    `TransformProvenance` has no `details` field. First-match precedence is
    verified via package.json file content instead.
