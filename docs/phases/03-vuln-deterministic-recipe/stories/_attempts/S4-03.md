### Trade-offs pinned

#### 1. `JailSetupFailed` reused; new `SubstrateSetupFailed` not introduced (AC-21)

The hardened story's AC-21 names a `SubstrateSetupFailed(reason, stderr_excerpt)` variant. The S4-01 sum
already ships `JailSetupFailed(reason: Literal[...closed set], detail: str)` with `kernel-setup-failed`
already covering "substrate refused to stand up the jail." Per Rule 7 (surface conflicts, don't average),
adding a parallel variant with overlapping semantics would have been duplicative — the macOS adapter
maps substrate parse errors to `JailSetupFailed(reason="kernel-setup-failed", detail=excerpt)`. The story's
intent ("typed, not sentinel `Completed(exit_code=N)`") is honoured: the variant is typed and discriminated;
the wire shape is just `JailSetupFailed` rather than a new sibling. Surface as doc-debt amendment to AC-21
if a future bake test demands a literal `SubstrateSetupFailed` name.

#### 2. Kernel symbol name: `classify_outcome` (not `_classify_outcome`) (AC-23)

The story header + AC-23 test sketch refer to `_classify_outcome`; the S4-02 hardening extracted the kernel
as the public `classify_outcome` symbol in `src/codegenie/transforms/sandbox/_classify.py`. Per Rule 11
(match the codebase's conventions), the macOS adapter imports `classify_outcome` verbatim and the AC-23
identity test asserts `bwrap.classify_outcome is sandbox_exec.classify_outcome` (function-object identity
beats name-string identity for the test's actual intent — proving no shadow copy). `bwrap.__all__` was
extended to expose `classify_outcome` so the meta-test can reach the symbol without `getattr`.

#### 3. macOS 14+ gate ships in `sandbox_exec.py`, not `sandbox_jail.py`

`SubstrateUnsupportedError` is a typed exception raised at construction time. It is adapter-local rather
than a sum-type variant (which is for *run-outcome* failures only) — defined in `sandbox_exec.py`. A future
`FirecrackerAdapter` or `DinDAdapter` can mirror the pattern without polluting `sandbox_jail.py`'s public
result surface.

#### 4. Pre-S4-05 `ALLOWED_BINARIES` posture (AC-10 / AC-11)

`sandbox-exec` is intentionally NOT in `ALLOWED_BINARIES` until S4-05. Integration tests therefore accept
both `Completed` (post-S4-05) and `JailSetupFailed(reason="binary-not-allowlisted")` (pre-S4-05) — same
documented pattern as `tests/integration/transforms/test_bwrap_hello_world.py`. The substitution
captures unambiguously: once S4-05 admits the binary, the test must produce `Completed` (otherwise the
nightly fails loud).

#### 5. Hypothesis fixtures: module-level path (no `tmp_path_factory`)

Hypothesis cannot inject pytest fixtures into a `@given`-decorated test. The three property tests use a
module-level `_HYPOTHESIS_TMP = Path(__file__).parent` — any existing directory suffices because the
spec.cwd value is only relevant as a literal in the rendered output (which the properties already check
via substring presence, not via filesystem effects).

#### 6. Template comment-stripping in AC-15

The packaged `.sb` profile carries `;;`-prefixed documentation lines that legally mention sandbox-exec
forms by name (e.g., "renders one `(allow network* (remote tcp ...))` per host"). AC-15's mutant guard
fences active clauses; the test pre-strips comment lines so a docstring mention does not trip the
sweeping-allow assertion.
