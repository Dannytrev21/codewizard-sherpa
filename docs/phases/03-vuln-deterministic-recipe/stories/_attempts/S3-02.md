### Refactor decisions

- **NULL-as-distinct in sqlite UNIQUE constraint defeats INSERT OR IGNORE.**
  Sqlite (without `NULLS NOT DISTINCT`, which is a 3.40+ syntax) treats
  every NULL as distinct from every other NULL, so two records with
  identical `(cve, eco, pkg, introduced, fixed, last_affected=NULL)`
  insert as two rows. Resolution: coalesce `None → ""` at the
  `_raw_insert` storage boundary AND restore `"" → None` at the
  `_row_to_record` / `affecting_range` read boundary. Schema columns
  remain `NULL`-able per AC-D1; the empty-string sentinel is an
  internal storage detail. `AffectedRange.fixed`/`last_affected`
  validators still reject empty strings when present (caller contract
  preserved). This was found mid-implementation by AC-D4
  (`test_insert_or_ignore_idempotent`) — a single behavioral test
  caught the entire NULL-semantics class.
- **`Ecosystem` (Literal) lives in `identifiers.py` alongside `PackageName`
  (NewType).** `Ecosystem` is a closed-set Literal, not a NewType, so the
  S1-01 fence tests had to grow a `PHASE3_LITERAL_NAMES` set distinct
  from `PHASE3_NAMES` (mirror of how `PackageManager` was already
  excluded from `test_pairwise_distinct`). Same pattern.
- **Alembic invocation in-process via `command.upgrade(cfg, "head")`.**
  Lazy-imported inside `_upgrade()` and the test fixture. Cold-start
  fence (`test_cold_start.py`) is load-bearing: subprocess `sys.modules`
  diff after `import codegenie.vuln_index`. `ALLOWED_BINARIES` was NOT
  amended; no subprocess used.
- **Migrations subpackage excluded from per-submodule cold-start fence.**
  `codegenie.vuln_index.migrations.env` and the initial revision
  module both import `alembic` at module top — they're internal
  plumbing only invocable via `command.upgrade`. Added to
  `tests/fence/test_per_submodule_cold_start.py::_SKIP` with a
  reason-citing comment.
- **`mtime`-after-open in tests.** `VulnIndex.__init__` opens the
  sqlite connection + applies WAL pragmas, which may bump the file's
  mtime. Tests pin `os.utime(...)` AFTER `VulnIndex(db)` so the
  staleness check sees the test-intended value.
- **Empty-DB digest pinned to `64bb3c9a3...262f2e8f`.** Computed once
  on first green run; frozen as the drift sentinel. Joiner / field
  order / hash-algorithm changes will fail this assertion loudly.
- **Pre-commit mypy hook's `additional_dependencies` mirrors runtime
  closure.** Added `alembic>=1.13` + `sqlalchemy>=2`. The isolated
  hook environment must resolve stubs for lazy-imported modules.
- **`uv.lock` regenerated** via `uv lock` (added 4 transitive packages:
  alembic, sqlalchemy, mako, greenlet). `test_uv_lock_is_in_lockstep`
  pins this.

### Lessons (cross-story candidates)

- **Sqlite UNIQUE constraints + nullable columns + INSERT OR IGNORE
  = silent duplicates.** Sqlite < 3.40 has no `NULLS NOT DISTINCT`
  syntax. For idempotent ingest where the unique key spans nullable
  columns, coalesce NULL → empty-string (or another sentinel) at the
  storage boundary. Document the round-trip explicitly so the
  contract on the typed model (`field: str | None`) stays clean.
  Catch this with a behavioral test (`double-insert ⇒ rowcount == 1`),
  not a structural one — the structural test (column nullability)
  passes both ways.
- **Cold-start fences need TWO scopes.** `tests/unit/{pkg}/test_cold_start.py`
  fences the deliberate-lazy-import surface (this story's heavy
  dependencies). `tests/fence/test_per_submodule_cold_start.py`
  fences *every* submodule's importability in a fresh subprocess.
  Alembic migration scripts belong to the first scope (they're
  meant to be lazy + Alembic-context-dependent) but break the
  second scope unless explicitly skipped. Add new internal plumbing
  to `_SKIP` with a reason-citing comment whenever it's not safe
  to import standalone.
- **Test seam typing matters.** `_raw_insert`/`_raw_set_meta` are
  test seams S3-03 will consume. Typing them strictly at the
  boundary (`isinstance` raise on bad input) means S3-03 catches
  bad calls at the seam, not deep in the sqlite driver.
