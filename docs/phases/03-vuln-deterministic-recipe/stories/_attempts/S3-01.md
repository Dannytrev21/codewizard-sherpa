### Refactor decisions

- **`_validate_namespace_keys` doubles for inner-key + list-element
  validation.** AC-17 forced this single-helper discipline; the inner
  capability-name walk in `provides` and the list-element walk in
  `requires` both route through the helper. The list-element walk
  uses an ad-hoc `{n: None for n in names}` mapping to fit the
  helper's `Mapping[str, object]` signature without inventing a
  second helper. Justified by Rule 3 (surgical changes) + the
  story's mandatory rule-of-three pin.
- **Forward-ref via `from __future__ import annotations` +
  `ContextQuery.model_rebuild()`** — matches Phase-2
  `src/codegenie/tccm/model.py` convention; no `ForwardRef` /
  `update_forward_refs()` (deprecated in Pydantic v2).
- **`TCCMParseError` is a frozen Pydantic `BaseModel`, not a
  `CodegenieError` subclass.** Per the Validation notes; the
  markers-only discipline in `codegenie.errors` would forbid carrying
  the `reason` / `details` payload the call site reads.
- **`PrimitiveName` direct-wrap** — `ContextQuery.create` skips
  `codegenie.types.parsers.parse_primitive_name` because its regex
  (`^[a-z][a-z0-9_]*$`) rejects dotted primitives like `scip.refs`.
  Cited inline in `tccm.py` near the wrap site.

### Lessons (cross-story candidates)

- **Validator helpers that route a single regex through one call site
  are AST-fenceable.** Counting raw substrings in the source text is
  cheap, mutation-resistant, and pins the rule-of-three discipline
  much more strongly than a passing test would alone.
- **Pydantic + `dict` field = unhashable.** Don't claim "frozen ⇒
  hashable" — pin both: `hash()` raises (negative test) and
  `model_dump_json()` is the actual cache-key surface (positive
  test).
