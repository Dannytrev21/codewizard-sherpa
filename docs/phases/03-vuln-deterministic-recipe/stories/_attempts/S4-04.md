### Implementation choices

#### 1. Field shape — public `absolute: Path`, not `_absolute: Path` (PrivateAttr)

The story sketch left the choice open: "use a private attr via Pydantic
private-attr if needed, OR expose as a regular field with a leading-underscore
name validated by Pydantic — pick the shape that survives the AC-Sub-3
round-trip test." I picked **public `absolute: Path`** for three reasons:

1. AC-2 specifies `sp.absolute == ...resolve()` — the public attribute name
   is `absolute`. Using a private `_absolute` + property would have meant
   `sp._absolute` for mutation tests and `sp.absolute` for value reads — two
   names for one field is a Rule-7 (surface conflicts, don't average) smell.
2. Pydantic v2 `PrivateAttr` is set via `model_post_init` or
   `object.__setattr__` — neither shape lets `cls(absolute=resolved)` carry a
   resolved-Path payload through the smart constructor. The regular-field
   shape is one clean line.
3. AC-6a's frozen-discipline test now reads `sp.absolute = Path("/etc")`
   (one-line edit from the story's `sp._absolute = ...` sketch). The
   ValidationError that fires is the same; the discipline being verified
   (frozen reassignment) is the same.

#### 2. Broken-symlink disambiguation via `candidate.is_symlink()`

`Path.resolve(strict=True)` raises `FileNotFoundError` for both a missing
leaf and a broken-symlink leaf (verified empirically). AC-5 demands the two
be strictly disjoint (`missing` vs `not_resolvable`). The smart constructor
disambiguates with `candidate.is_symlink()` (lstat-based, no follow) inside
the `FileNotFoundError` handler — broken-symlink-as-link maps to
`not_resolvable`; genuinely-missing leaf maps to `missing`.

#### 3. `IO[bytes] | IO[str]` return type (no `Any`)

The story's sketch returned `IO[Any]`; the Phase-3 `Any`-fence
(`tests/fence/test_no_any_in_plugin_surface.py`) rejects that, and the
"zero allowlist markers at Step-1 landing" floor rules out `# fence: any-allowed`.
The return type is now `IO[bytes] | IO[str]` with a `typing.cast` of
`os.fdopen`'s result; the runtime semantics are unchanged.

#### 4. `__fspath__`, `__str__`, `__truediv__` delegates

Post-flip, downstream code that did `cache_dir / "bundles"`,
`tempfile.NamedTemporaryFile(dir=cwd)`, or `str(spec.cwd)` would silently
break because Pydantic `BaseModel`'s default `__str__` is `field=value`.
Three small delegates restore the ergonomics WITHOUT making SandboxedPath
look like a Path (`isinstance(sp, Path)` is still False, and `__truediv__`
returns a *bare* Path — composition does not propagate the capability):

- `__fspath__` → `str(self.absolute)` — `os.*` functions accept it.
- `__str__` → `str(self.absolute)` — `str(sp)` returns the path string for
  templates / logs.
- `__truediv__` → `self.absolute / other` returning bare `Path`. Capability
  composition would re-require `.create()`.

#### 5. Adapter-side unwrap to `Path`

`SandboxExecAdapter` and `BwrapAdapter` previously passed `spec.cwd`
(`SandboxedPath` after the flip) to `run_allowlisted(..., cwd: Path)` and
`_write_profile(cwd: Path, ...)`. `mypy --strict` flagged the type mismatch.
I unwrapped at the OS-call boundary (`spec.cwd.absolute`) — the adapter
owns the capability; the OS layer takes the underlying Path. This is the
architecturally honest split: SandboxedPath is the capability surface;
`Path` is the kernel-syscall surface.

#### 6. Test-isolation fix in `test_no_llm_in_transforms.py`

S4-04 introduced `codegenie.transforms._forward → codegenie.plugins.sandbox_path`,
so popping `codegenie.plugins.*` from `sys.modules` (the planted-positive
test does this to force re-import of the walker's targets) creates a NEW
`SandboxedPath` class identity, which breaks `A is B` checks and Pydantic
`model_type` validation in tests collected before that point.

The fix is one-sided: the planted-positive test now scopes its pop+restore
ONLY to `codegenie.plugins.*` (the planted module is in `plugins/`, so the
walker's transforms scan is a cache hit anyway — popping transforms is
gratuitous and breaks downstream identity). Snapshot/restore at the
plugins boundary keeps class identity stable for every test collected
before this fence runs.

### Trade-offs deliberately taken

#### 1. ADR-0001 amendment is implicit, not a fresh ADR

The flip admits ONE re-export from `codegenie.plugins.sandbox_path` into
`codegenie.transforms._forward`. `_forward.py`'s docstring already
anticipated this ("S4-04 — Replace …"); the fence allowlist amendment in
`tests/fence/test_transforms_module_purity.py` is the structural record.
The inverse direction (`plugins.sandbox_path → transforms`) remains
forbidden — fenced by the new `tests/fence/test_plugins_sandbox_path_purity.py`.
No fresh ADR was written; per Rule 2 (Simplicity First), the existing
ADR-0011 already names this transition.

#### 2. AC-16 / AC-17 explicitly deferred (per story)

- **AC-16** (consumer-side `try/except OSError` + `with_sandbox_open` helper)
  lands when S5-02's `NpmLockfileRecipeEngine` is the first real consumer,
  or with S4-05's capability-fence layer. Adding it now without a consumer
  is premature (Rule 2).
- **AC-17** (custom ruff rule banning direct `SandboxedPath(...)` outside
  `sandbox_path.py` + `tests/`) lands with S4-05. ADR-0011 §Consequences
  names `tooling/ruff_rules/no_capability_construction.py` as the home.

#### 3. `_check_under_jail` extraction deferred

Single call site today; Rule 2 (Simplicity First) wins. Notes-for-implementer
captured the trigger condition: when `create()` grows a second under-jail
check, extract then.
