# Validation report — Story S7-04 — Concurrent-remediate `fcntl.flock` + `RepoAlreadyInProgress`

**Story:** [`../S7-04-concurrent-remediate-repo-lock.md`](../S7-04-concurrent-remediate-repo-lock.md)
**Validated:** 2026-05-26
**Validator:** `phase-story-validator` (single-agent inline mode)
**Validator agent run:** automated (`story-validation-corrector` scheduled task)
**Verdict:** **HARDENED**

## Summary

S7-04 closes Phase 5 Edge Case 18 by adding an `fcntl.flock`-based exclusive lock at `.codegenie/remediation/.lock` so two concurrent `codegenie remediate` invocations on the same repo cannot interleave writes to `attempts.jsonl`, the cost ledger, or the per-attempt sandbox dirs. The draft's goal + scope were directionally correct — right lock primitive, right placement before `record_pre_execute` (ADR-0007), right second-process-refusal contract. But every block-tier finding traced to one of three root causes:

1. **The story was written before S1-01 reached HARDENED on 2026-05-16.** S1-01 AC-2 + AC-7 froze `RepoAlreadyInProgress` as a bare-marker class subclassing `SandboxError` (Exception-passthrough; no custom `__init__`; no class attributes; no `__str__` override). S7-04 AC-1 said `class RepoAlreadyInProgress(CodegenieError)` *with* `lock_path: Path` and `holder_pid: int | None` attributes — wrong base, forbidden attributes. The TDD plan then accessed `excinfo.value.lock_path` directly, which would `AttributeError` against the actual S1-01-locked class.
2. **The story was written before S1-01 froze the `sandbox/logging.py` event-constant kernel.** S1-01 extension-by-addition contract requires every new event name to be appended as a `Final[str]` constant in `sandbox/logging.py` (under `__all__`, dotted-lowercase, ≥ one dot). S7-04 AC-7 emitted `repo_lock.acquired` / `repo_lock.released` as bare string literals — bypasses the kernel and the audit-string rename test S1-01 ships.
3. **The story was written before S5-02 reached HARDENED on 2026-05-25.** S5-02 froze `GateRunner.__init__` keyword-only with 6 deps and `run` as `async def`; S7-03 already added `cost` as the additive 7th keyword. S7-04 implementer-outline step 4 left the wiring point ambiguous between `GateRunner.__init__` and `cli/remediate.py` — but the lock's natural lifetime is the *whole* remediate invocation (the orchestrator constructs one `GateRunner` per gate; the lock must span every gate plus Phase 3/4 work). The wiring point is the CLI/orchestrator entry, not `GateRunner.__init__`.

Counting: **23 findings — 9 block-tier, 11 harden-tier, 3 nit-tier.** The blocks would have produced reachable structural bugs the executor's validator would have missed: `AttributeError` on `excinfo.value.lock_path` (no such attribute on a marker class); ad-hoc `"repo_lock.acquired"` strings that the S1-01 rename test would flag; an 8th-keyword bloat of `GateRunner.__init__` that breaks the S5-02 ctor signature snapshot; `FileNotFoundError` from `open()` on uninitialized repos (parent dir not created); `ValueError` swallowing the intended `RepoAlreadyInProgress` on a torn or empty PID body; and a racy subprocess test that passes on slow CI even without the lock.

The hardens close mutation-resistance gaps (the lock-order invariant — `flock` before truncate-and-write — is never tested by the draft; a test that mocks `flock` to fail must assert the file body is *untouched*), pin the structlog field shape to S5-02's per-event-field discipline, surface the functional-core/impure-shell split (a pure `_parse_holder_pid(body) -> RepoLockHolder | None` falls out cleanly), and tie loose ends to CLAUDE.md commitments (extension-by-addition for the new `cli/exit_codes.py` kernel; structural fence under `tests/fence/` for the new `sandbox/repo_lock.py` module).

**No `RESCUE`-tier findings.** The goal traces cleanly to `phase-arch-design.md §Edge cases row 18` + ADR-0007; every gap was patchable by pinning against HARDENED siblings (S1-01, S1-04, S5-02, S7-03) and Phase 0 precedents (`src/codegenie/errors.py` marker-class shape, `src/codegenie/logging.py` `EVENT_*` discipline). **No Stage-3 research needed** — all findings answerable from in-repo sources + the `fcntl(2)` / `flock(2)` man pages.

## Context Brief (Stage 1)

### Story snapshot

- **Goal (verbatim):** Land `fcntl.flock(LOCK_EX | LOCK_NB)` acquisition at `.codegenie/remediation/.lock` on `GateRunner` (or orchestrator) start, with a `RepoAlreadyInProgress` error raised on contention and a real-process integration test that proves the second `codegenie remediate` exits cleanly.
- **Non-goals (Out-of-scope, hardened):** Cross-host locking (Phase 9 Temporal); `--force-unlock` / `codegenie sandbox unlock`; lock-holder identity beyond PID; migrating non-locked legacy runs; introducing a `RepoLock` Protocol (Rule 2 cap — only one consumer); editing S5-02-locked `GateRunner.__init__` parameters; editing the S1-01-locked `RepoAlreadyInProgress` class body (already a bare marker — extension is at the catch site, not the class).

### Phase 5 exit criteria touched

- **Step 7 done-criteria (`High-level-impl.md §Step 7`):** "Adversarial concurrency: `tests/integration/sandbox/test_concurrent_remediate.py` — second concurrent `codegenie remediate` on same repo exits with `RepoAlreadyInProgress` via `fcntl.flock` on `.codegenie/remediation/.lock`."
- **`phase-arch-design.md §Edge cases` row 18:** the verbatim behavior spec.
- **ADR-0007:** lock must wrap the marker — `acquire_repo_lock` enters before `RetryLedger.record_pre_execute` is callable; a `pre_execute` JSONL line cannot exist outside the lock.

### Load-bearing commitments touched

- **CLAUDE.md "Match the existing convention":** `RepoAlreadyInProgress` is already a bare-marker `SandboxError` subclass per S1-01 (the Phase-0 marker-class shape). Re-defining it with class attributes is convention drift, not a deliberate departure.
- **CLAUDE.md "Extension by addition — no silent edits":** new event constants extend `sandbox/logging.py` `__all__`; new exit codes extend the new `cli/exit_codes.py` kernel; never rename or re-value an existing entry. The S1-01 audit-string rename test would flag a literal `"repo_lock.acquired"` that is not declared in `sandbox/logging.py`.
- **CLAUDE.md "Make illegal states unrepresentable":** the `lock_path`/`holder_pid` tuple is a value type, not a bag-of-attributes on an exception. A frozen `RepoLockHolder` model (`extra="forbid"`) carries the pair through `structlog.bind(...)` at the raise site; the catch-site reads structured fields, not exception attributes.
- **CLAUDE.md "Functional core / imperative shell":** S7-02 + S7-03 HARDENED established this pattern; S7-04 is the third concrete consumer — split `_parse_holder_pid(body) -> RepoLockHolder | None` (pure) from `acquire_repo_lock` (impure context manager wrapping `os.open` / `fcntl.flock` / `os.write` / `os.fsync` / `os.close`).
- **CLAUDE.md "Structural defenses live under `tests/fence/`":** new `src/codegenie/sandbox/repo_lock.py` submodule + new `src/codegenie/cli/exit_codes.py` submodule both require fence coverage (cold-start clean; no banned imports; constants typed `Final[int]` / `Final[str]`).

## Conflict resolutions

- **Coverage wanted `lock_path` + `holder_pid` as exception attributes vs Consistency forbids it (S1-01 AC-2).** Consistency wins (source-of-truth is S1-01 HARDENED). The pair travels via a frozen `RepoLockHolder` value type bound through `structlog` and serialized as the exception's `str()` payload (json). The catch-site reads structured fields, not exception attributes.
- **Design-Patterns wanted a `RepoLock` Protocol vs Rule 2 ("three similar lines is better than premature abstraction").** Rule 2 wins — only one consumer today. Pattern advice landed in Notes for the implementer §"Future seam for Phase 9 (Temporal)" with explicit promotion conditions ("if Phase 9 lands a `TemporalRepoLock` adapter, lift `RepoLock` Protocol then"), NOT as an AC.
- **Coverage wanted "wire in `GateRunner.__init__`" vs Consistency (S5-02 keyword-only ctor frozen + lock spans whole remediate).** Consistency wins. The lock is acquired at `cli/remediate.py` Click-command entry, wrapping the entire downstream pipeline (Phase 3 → 4 → 5). `GateRunner.__init__` is unchanged.
- **Design-Patterns wanted `RepoLockHolder` as a `dataclass` vs Consistency (Phase 5 uses frozen Pydantic `extra="forbid"` for value types per S1-04 AC-4).** Consistency wins — Pydantic `BaseModel(model_config=ConfigDict(frozen=True, extra="forbid"))`.
- **Coverage wanted the integration test to assert "exit code 14 within 5 seconds" vs Test-Quality wanted "exit code 14 with no time bound".** Test-Quality wins on the bound itself (5 s is arbitrary), but Coverage wins on the deterministic synchronization (FIFO instead of sleep). Final: deterministic FIFO-based synchronization; the `proc.wait(timeout=30)` exists as a *test infrastructure* guard against test hangs, not as a behavioral assertion.
